# Открытое ядро RealtimeCSG: первичный разбор

Цель: открытая реализация геометрического ядра для Unity 2022 LTS на Linux,
с последующей проверкой новых версий Unity. Рабочее предположение — Linux x86_64;
дистрибутив и точное исключение при загрузке пока неизвестны.

## Что установлено по этой копии

- `LICENSE.md` содержит MIT; README прямо сообщает, что исходники C++ не опубликованы.
- `package.json`: пакет 1.60.1, заявленная минимальная Unity 2018.4.
- Нативный модуль называется `RealtimeCSG[1_559]`:
  `Plugins/API/Foundation/Editor/Native/CSGManager.Native.cs`.
- В `Plugins/Editor/External` есть Windows PE x86_64 DLL и macOS Mach-O x86_64 bundle.
  Linux ELF `.so` отсутствует. Изменение расширения или PluginImporter не создаёт Linux-сборку.
- Интерфейс редактора, компоненты, создание/валидация BrushMesh и структуры обмена доступны в C#.
  Реализация дерева и вычислений вызывается через P/Invoke.
- Найдены 105 объявлений P/Invoke к ядру, 79 уникальных имён и 101 именованный экспорт DLL.
  Это статическая инвентаризация, включая объявления под условной компиляцией,
  а не число функций, вызываемых в конкретном запуске Unity.
- `LogDiagnostics` объявлена в C#, но не экспортируется этой DLL. Поиск по `Plugins`
  нашёл только объявление, поэтому это само по себе не объясняет ошибку загрузки.
- 23 экспорта DLL не имеют соответствующего прямого объявления в просмотренных C#-привязках.
  Их отсутствие в новой библиотеке нельзя считать безопасным для сторонних клиентов автоматически.

## Где проходит граница

| Область | Доступный контракт | Что предстоит реализовать |
| --- | --- | --- |
| Дерево | `Plugins/API/Foundation/Editor/Native/CSGTree*.Native.cs` | ID, родители, порядок детей, операции, dirty-состояние, трансформации |
| Входная геометрия | `BrushMesh.cs`, `Native/BrushMeshInstance.Native.cs` | Хранение вершин, half-edge и полигонов, обновление/удаление |
| CSG и выдача мешей | `Native/CSGTree.Native.cs` | Булевы операции, описания/буферы мешей, нормали, UV, tangent, bounds |
| Выбор | `Plugins/Editor/Scripts/Control/Bindings/NativeMethodBindings.cs` | Raycast, frustum, связь результата с brush и surface |
| Контуры | Там же, `GetBrushOutline*`, `GetSurfaceOutline*` | Видимые/скрытые линии, версии контуров |
| Вспомогательная геометрия | Там же, `Decompose*`, `Convert*Coord` | Выпуклое разбиение 2D и преобразования UV |
| Инициализация | `Control/Managers/UpdateLoop.cs`, `NativeMethodBindings.cs` | Регистрация callbacks и жизненный цикл библиотеки |

Пути без общего префикса в первых трёх строках относятся к
`Plugins/API/Foundation/Editor/`.

`NativeMethods` — таблица делегатов для редактора, но это не единственная точка
доступа: Foundation API вызывает DLL напрямую. Подмена только таблицы делегатов
не покрывает весь публичный API.

## Воспроизводимый анализ

Из корня репозитория, Python 3 и GNU objdump:

```sh
python3 tools/native_audit.py --output /tmp/realtime-csg-native-api.json
python3 tools/native_audit.py --disassemble HasBeenCompiledInDebugMode
python3 tools/native_audit.py --disassemble GenerateTree
```

Инструмент не загружает DLL. JSON содержит исходные объявления с путями и строками,
SHA-256 DLL, имена экспортов, RVA, виртуальные адреса и расхождения.
Парсер намеренно ограничен текущим стилем объявлений и завершится ошибкой при
нераспознанном `DllImport`. Он не вычисляет условия `#if` и размеры ABI-структур.

Дизассемблирование охватывает интервал до следующего экспортированного адреса
(либо 256 байт для последнего экспорта); внутри могут быть другие функции.
Это не восстановленная граница функции и не C++-исходник.

Первые наблюдения для DLL с SHA-256
`46419e6d331e01089678e9148ec4cd7746926e4b1b0c36bf619cbd05c9701bf2`:

- `HasBeenCompiledInDebugMode`, RVA `0x4b020`: `xor al, al; ret` — возвращает false.
- `GenerateTree`, RVA `0x56720`: проверяет выходной указатель; успешный путь
  записывает 32-битное значение из внутреннего объекта плюс один и возвращает
  `AL = 1`; путь ошибки при ненулевом выходном указателе записывает 0 и возвращает
  `AL = 0`. Значение поля и политика выделения ID требуют дальнейшего анализа.

## Предлагаемая реализация

Самостоятельное переносимое ядро на C++ с C ABI и тонким адаптером к существующим
привязкам. Это позволяет оставить текущие C#-инструменты и сцены основой проекта.
Дизассемблирование использовать для конкретных вопросов поведения, когда
документация и C#-обёртки не дают ответа. Исходный C++ по экспорту восстановить
в первоначальном виде нельзя; открытое ядро предстоит написать и проверить.

1. **Зафиксировать ABI и поведение дерева.** Подготовить CMake-сборку Linux,
   структуры и явные правила передачи данных. Проверить размеры/смещения структур
   против `Marshal.SizeOf`/`Marshal.OffsetOf` в Unity. Реализовать создание,
   удаление, иерархию, dirty и трансформации. Отдельно установить поведение при
   неверных ID, циклах, переносе детей и удалении узлов.
2. **Пройти вертикальный путь одного brush.** Передать куб из существующего
   BrushMesh, получить описания и буферы меша, показать его в Unity 2022 LTS Linux.
   Сначала проверить этот путь через Foundation API; обычный редактор также
   потребует callbacks, выбора и контуров.
3. **Добавить булевы операции.** Начать с плоских граней выпуклых brushes и
   разрезания полигонов плоскостями. Проверить union, subtract и intersect на
   двух кубах, затем порядок операций и вложенные ветви. Через разрезания
   сохранять brush/surface ID и атрибуты исходных граней. Отдельные случаи:
   совпадающие плоскости, касания, тонкие фрагменты, вырожденные полигоны,
   отрицательный масштаб. Выбор алгоритма и численных допусков ещё не подтверждён.
4. **Восстановить работу редактора.** Raycast и выбор поверхностей, контуры,
   UV, материалы и группировку submesh, collider queries, convex decomposition,
   обновления после undo/redo и перезагрузки domain. Сравнить поведение с оригиналом
   на Windows/macOS, если доступна среда запуска оригинала.
5. **Проверить переносимость и скорость.** Повторить тестовые сцены на целевых
   версиях Unity и ОС; после корректности внедрять кэширование и частичные
   перестроения. Поддержку более новых Unity объявлять после фактических проверок.

Критерии геометрических проверок: замкнутость результата, согласованная ориентация,
ожидаемый объём/bounds, отсутствие вырожденных треугольников и сохранение surface
атрибутов. Совпадение порядка вершин и треугольников с оригиналом не является
обязательным критерием геометрической эквивалентности.

## Существенные детали совместимости

- Контракт использует `CallingConvention.Cdecl`, структуры с `Pack = 4`, enum
  `CSGOperationType : byte`, указатели на закреплённые массивы и callbacks.
  Нельзя механически преобразовать все enum в `int`, а все `bool` в один тип:
  требуется проверить managed marshalling и нативную сторону для каждого случая.
- Буферы геометрии выделяет C#; библиотеке нужно соблюдать ёмкости, правила
  необязательных каналов и время жизни указателей. Описания мешей и их последующая
  выдача образуют протокол из нескольких вызовов.
- Для Linux требуется ELF-библиотека и корректная конфигурация Unity PluginImporter.
  Одна успешно загруженная `.so` ещё не означает работоспособный CSG-редактор.
- Этот документ сохраняет первоначальный план. Текущий результат описан в
  [отчёте восстановления](native-recovery.ru.md) и
  [scene bridge / Unity smoke](recovery/scene-bridge.ru.md): открытый выпуклый
  конвейер и отдельный C# ABI уже выполняются в Unity 2022.3.62f3 Linux;
  существующий редактор ещё не подключён.
