# MergeBrushIndices: объединение пары групп

В `native/recovered/brush_edge_cleanup.cpp` добавлен `mergeBrushIndexPair`,
восстанавливающий форму вызова `MergeBrushIndices(..., indices, 2)`.
Именно её использует CleanUpBrushEdges при разных назначенных source indices
двух сторон ребра. Конфликтующий путь подключён к cleanUpBrushEdges.
Массивы из трёх и более индексов, встречающиеся в других стадиях, этим API
ещё не поддерживаются.

Источник — Mach-O x86_64 RealtimeCSG 1.559, SHA-256
`26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.
MergeBrushIndices: `0x3218e..0x32a76`; вызов с count=2 в CleanUpBrushEdges:
`0x34ff6..0x3502c`.

## Выбор группы и изменение входного массива

Исходная функция сначала сортирует индексы по убыванию. Для пары:

* два -1 дают результат -1 без изменений групп/triangle tags;
* один -1 оставляет назначенный индекс первым и возвращает его;
* одинаковые назначенные индексы возвращаются без объединения;
* для разных назначенных индексов порядок затем разворачивается в возрастающий.

При настоящем объединении сохраняется группа с меньшим индексом.
Она сохраняет surfaces, line record, triangle-handle list и connections.
Списки triangle handles и connections удаляемой группы к ней не добавляются.
Portable API требует -1 или действующие индексы; другие значения отклоняются
до мутации вместо исходного небезопасного разыменования.

## SurfaceRefs и повторы

Для каждой исходной ссылки сохраняемой группы ищется первое равное вхождение
в удаляемой. Найденная пара помечается `{-1,0xffffffff}`.
Затем оставшиеся ссылки удаляемой группы с brush ID != -1 дописываются
в сохраняемую в исходном порядке.

Это не обычный set union. Два вхождения (5,7) в сохраняемой группе и три
в удаляемой дают в итоге три вхождения. ID -1 в удаляемом списке пропускается,
остальные отрицательные ID исходный алгоритм допускает.
Существующие ссылки сохраняемой группы не очищаются и не сортируются.

## Удаление и remap

Если удаляемая группа не последняя, последняя перемещается на её место.
Теги удаляемой переназначаются сохраняемой, теги бывшей последней —
на освободившийся индекс. Метаданные и все три списка перемещаются вместе.

При удалении последней группы исходный путь уменьшения vector перезаписывает
её remap-значение в -1 (`0x32685..0x32697`). Прочие triangle tags с этим индексом
очищаются, хотя refs уже добавлены в сохраняемую группу. Эта особенность
проверенного бинарника воспроизведена и отдельно покрыта тестами.

Helper применяет remap ко всем triangle edgeSource в меше. Значения вне
старого массива нормализуются в -1; исходный -1 сохраняется.
При раннем возврате без настоящего объединения нормализация не выполняется.

CleanUpBrushEdges перед вызовом очищает source tags самой конфликтующей пары,
затем после общего remap записывает возвращённый индекс в обе стороны.
Поэтому эта пара сохраняет связь с итоговой группой и при удалении хвоста.
Проход продолжает обход с актуальными группами и индексами, включая следующие
конфликты, видимость, окончательное уплотнение и заполнение списков.

## Память и ошибки

C-функция `rcsg_recovered_merge_brush_pair` получает изменяемую пару,
groupCount и выходной selectedIndex. Статусы: 0 успех, -1 неверный вход,
-2 недостаточная ёмкость, -3 прочая ошибка. selectedIndex может быть -1
при успешной обработке пустой пары.

Объединение и весь CleanUpBrushEdges выполняются на временной копии triangle
records и содержимого групп. С каждой группой сохраняются её caller-owned views,
поэтому перестановка переносит нужные буферы и ёмкости. До записи проверяются
размеры всех итоговых активных списков. Ошибка оставляет исходные треугольники,
группы, groupCount, входную пару и selectedIndex неизменными.
Удалённые слоты сохраняют caller-owned буферы с нулевыми counts.
Владение памятью не передаётся через API.

Это исследовательская организация памяти с дополнительным копированием;
она не реализует внешний ABI Unity-плагина.

## Сравнение с оригиналом

`tools/compare_merge_brush_pair.py` вызывает неизменённый MergeBrushIndices
с count=2. Сравниваются возвращённый индекс, все байты изменённой пары,
полный triangle buffer и все поля/списки активных групп.
Есть повторы surfaceRefs, пустые/одинаковые индексы, удаление хвоста и перенос
последней группы, произвольные прочие triangle fields, неверные edgeSource
за пределами массива и непустые source/connection lists.

При seed 1559: 5 000 пар, 2 909 настоящих объединений, из них 772 удаления
хвостовой группы. Расхождений нет.

`tools/compare_brush_edge_cleanup.py --merges` сравнивает полный оригинальный
CleanUpBrushEdges на входах с конфликтующими назначенными source indices,
включая последовательные объединения, общие remap и дальнейшую очистку:

| Показатель | Результат |
| --- | --- |
| Наборы с разрешёнными конфликтами | 5 000 |
| Удалённые группы | 33 356 |
| Записи в итоговых triangle lists | 133 042 |
| Сохранённые hidden/hidden теги | 43 052 |
| Расхождения triangle/group/list данных | 0 |

Прежние 5 000 входов без конфликтов также прошли без расхождений:
17 539 удалённых групп, 152 287 записей в итоговых списках.
Группы оригинала владеют host-выделениями: удаление, перестановка и освобождение
выполняются исходными helpers. Проверяется освобождение всех выделений.
В данных есть запас ёмкости; пути роста списков здесь исключены.

Четырнадцатый CTest проверяет оба удаления, повторы, сохранение root geometry/lists,
remap, early returns и ошибки до мутации. Тест CleanUpBrushEdges расширен
конфликтующей парой с успешным объединением. Все 14 CTest проходят в обычной
сборке и с ASan/UBSan (`ASAN_OPTIONS=detect_leaks=0`).

```sh
cmake --build /tmp/realtime-csg-recovery/build
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
python3 -B tools/compare_merge_brush_pair.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000
python3 -B tools/compare_brush_edge_cleanup.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000 --merges
```
