# Категоризация: операции и программы видимости

Добавлены `native/recovered/categorization.cpp` и публичный исследовательский
интерфейс `native/include/realtimecsg/recovered_categorization.h`.
Модуль строит программу для поверхности выбранного brush: сохранить её,
скрыть или развернуть после вычисления CSG-дерева.

Это **новый компилятор на основе восстановленных правил**, а не дословно
декомпилированный `GenerateCategorizationTable`. Нумерация состояний и сокращение
таблиц отличаются; проверяется совпадение конечных решений с оригиналом.
Полная геометрическая `CSGCategorizationStack::Categorize`, подготовка пересечений,
трансформации и `FindBrushEdges` ещё не восстановлены.

## Что извлечено из оригинала

Источник — тот же Mach-O x86_64 с SHA-256
`26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.

| Объект | Адрес |
| --- | --- |
| `CategoryStackNode::GenerateCategorizationTable` | `0x25456` |
| `AddToCSGStack` | `0x26950` |
| `CSGBrush::UpdateCategorizationTable` | `0x4604` |
| Упакованные таблицы `csg_operations` | `0x3c750` |
| Правила совпадающих поверхностей | `0x257f0`, `0x25aec` |
| Особый путь Infinite | `0x2599e` |
| Установка флага Infinite | `SetBrushFlagsIterative`, `0x2c229` |

Первые три 32-битных значения `csg_operations`:

- Additive: `0xe4a04400`;
- Subtractive: `0xffbb5f1b`;
- Intersecting: `0xffeef5e4`.

Каждая пара категорий занимает два бита по сдвигу `8*left + 2*right`.
Категории: Inside=0, Aligned=1, RevAligned=2, Outside=3. Все 48 комбинаций
эквивалентны следующим выражениям:

```text
Additive(a,b)     = a & b
Subtractive(a,b)  = a | ((~b) & 3)
Intersecting(a,b) = a | b
```

Категории кодируют две стороны поверхности. Результат Interior/Exterior скрывает
поверхность; Aligned сохраняет направление, RevAligned требует его разворота.
Итоговые состояния программы — Hidden=1, Aligned=2, ReverseAligned=3.
Их нельзя путать с категориями 0..3 или PolygonSplitResult.

## Порядок brushes и совпадающие поверхности

Поверхность выбранного brush рассматривается как Aligned относительно него самого.
Для остальных обычных brushes категория сводится к состоянию внутри/снаружи:

| Категория относительно другого brush | Он раньше выбранного brush в порядке дерева | Он позже |
| --- | --- | --- |
| Inside | Inside | Inside |
| Aligned | Outside | Inside |
| RevAligned | Inside | Inside |
| Outside | Outside | Outside |

Восстановленный порядок — обход листьев дерева слева направо, с сохранением
порядка детей и скобок вложенных операций. Нельзя заменить вложенную группу
плоским списком или выбирать владельца поверхности по числовому ID узла.
Ведущие вычитания/пересечения до первого Additive в группе пропускаются.

Leaf-подсказки пересечения: 0 — Outside, 2 — Inside, 1/3 — неразрешённая
зависимость от геометрии. Для выбранного brush используется его собственная
поверхность. Подсказки 0/2 позволяют удалить зависимость из программы.

Infinite не имеет собственных поверхностей. Для него в оригинале есть особый
путь: после начала группы он заменяет аккумулятор на Inside независимо от
сохранённого типа операции. Это подтверждено исполнением генератора, включая
необычное сочетание Infinite + Subtractive; код сохраняет наблюдаемое поведение.
Обычные булевы формулы к этому пути механически не применяются.

## Формат и реализация

Оригинальная запись перехода имеет 16 байт: int32 node по +0, int16 state по +4,
четыре int16 successor по +6/+8/+10/+12. Поле полигона по +18 теперь названо
`categorizationState`, поскольку его назначение подтверждено.

Переносимый вход дерева отделён от внутреннего `CSGNode`: плоский массив узлов
и отдельный массив индексов детей. Компилятор использует упорядоченные четырёхветочные
диаграммы решений с объединением одинаковых подграфов и мемоизацией операций.
Он не перечисляет все 4^N сочетания. После объединения скрытых конечных результатов
программа группируется по порядку brushes и исполняется последовательно.

Исследовательский C-интерфейс позволяет запросить размер, заполнить буфер переходов
и исполнить программу. Возвращаются отдельные ошибки для неподдержанного входа,
недостаточного выходного буфера и исчерпания лимита состояний/памяти.

## Эталонный запуск оригинального генератора на Linux

`tools/original_categorization.py` отображает статическое замыкание зависимостей
генератора: 17 исходных функций, включая его vector/hash вспомогательные функции.
Конструкторы Mach-O, Unity и полная библиотека не запускаются. Память разделена
на RX-код/константы и RW-данные; SHA-256 проверяется до выполнения.

Импорты malloc/free и операций с памятью перенаправлены в Linux libc. Функция
`libc++::__next_prime` заменена математическим поиском ближайшего простого числа;
это вспомогательная операция хеш-таблицы, а не логика CSG. Исключения и другие
системные пути не поддерживаются. Подготовлены искусственные manager, узлы
и TwoBitSet с наблюдаемым исходным форматом.

Существенное предусловие: вызывающий `UpdateCategorizationTable` резервирует
рабочий vector на **6 × число узлов** (`0x46ae`—`0x46be`). Генератор сохраняет
указатели в этот буфер при добавлениях. Эталон соблюдает тот же резерв;
вызов с пустой ёмкостью приводил к инвалидированию указателей и был исправлен.
Проверки ниже выполнены после исправления этого предусловия.

## Проверки и интеграция

```sh
cmake --build /tmp/realtime-csg-recovery/build
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
python3 -B tools/compare_recovered_categorization.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --trees 300
```

При seed 1559 проверены 48 пар категорий, 300 деревьев, 1 463 программы для
разных выбранных brushes и 148 552 конечных решения. Расхождений нет. Набор
включает вложенные группы, разные операции, порядок/числовые ID, совпадение
и противоположность поверхностей, Infinite и разрешённые leaf-подсказки.
Для небольших наборов листьев перебраны все категории, для остальных — выборка.
Не сравниваются номера состояний и порядок записей двух разных оптимизаторов.
Пустой результат оригинальной программы оставляет начальное состояние 0;
в сравнении результатов это отсутствие выжившей поверхности, как Hidden.

CTest дополнительно связывает модули: исходная поверхность разрезается
`SplitByPlane`, затем программа A-B скрывает часть внутри полупространства B
и сохраняет внешнюю часть. Проверяются и метки, и координаты фрагментов.
Это интеграция разрезания с решением о видимости, **ещё не вычитание двух объёмов**.
Последующий [геометрический проход](convex-csg.ru.md) уже связывает программу
с плоскостями выпуклых тел: проверены объёмные операции и вложенные группы.
Подключена также [восстановленная выпуклая триангуляция](triangulation.ru.md).
Все восемь CTest-тестов проходят также ASan/UBSan (без leak detection).

## Границы текущего этапа

- Требуется хотя бы один Additive-ребёнок в каждой ветви. Пустые и полностью
  неаддитивные группы явно отклоняются: подготовка их hints и эквивалентность
  оригиналу ещё не восстановлены, в искусственных входах получались иные результаты.
- Hints ветвей пока должны оставаться 1; разрешённые ветви с hints 0/2/3 не поддержаны.
- Дерево должно быть без циклов и общих детей; проверяются индексы, типы и глубина.
  Текущие исследовательские лимиты: 4096 узлов, глубина 256 и положительные int16-состояния.
- Для выпуклых тел в общем пространстве геометрические категории теперь готовит
  `categorizeConvexFragments`. Это новая организация восстановленных операций,
  не полное восстановление исходного Categorize. Трансформации, FindBrushEdges,
  полная подготовка/очистка треугольного меша и интеграция Unity остаются впереди.
