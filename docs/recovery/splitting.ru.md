# Восстановленное разрезание полигонов

В `native/recovered/splitting.cpp` перенесены три функции исходного macOS-ядра:

| Функция | Адрес начала |
| --- | --- |
| `BrushMemory::InsertVertexBetweenEdges` | `0x64b6` |
| `BrushMemory::SplitAtEdges` | `0x65f8` |
| `CSGBrushPolygonMesh::SplitByPlane` | `0x2d15c` |

Вспомогательные операции добавления вершины/ребра восстановлены по
`CreateLocalVertexIndex` (`0x6456`) и `CreateEdges` (`0x60da`). Источник — тот же
проверенный Mach-O с SHA-256
`26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.

## Что делает восстановленный код

Вставка вершины делит ребро вместе с его twin на соседней грани, меняет прямые
и обратные связи и счётчики обеих граней. Назначение дополнительного поля
`EdgeLinkRecord +4` пока неизвестно; оно сохраняется при вставке.

`SplitAtEdges` отделяет часть кольца в новый полигон, обновляет владельцев
рёбер и добавляет пару замыкающих twin-рёбер. Если обе границы используют один
vertex ID, применяется отдельная ветка без новых замыкающих рёбер.
В новый полигон копируются surfaceIndex и только младший байт PolygonFlags;
остальные нетронутые оригиналом поля остаются как были в буфере.

`SplitByPlane` использует восстановленный обработчик вершин из
[модуля классификации](plane-classification.ru.md). Точки пересечения вычисляются
с отрицательного конца ребра, затем последовательно корректируются на режущую
и исходную плоскости. Близкую уже созданную вершину можно использовать повторно.
Найдя обе границы, функция вызывает SplitAtEdges. Существующий полигон сохраняет
внутреннюю часть; выходной ID указывает на внешнюю. Для CompletelyOutside
выходной ID равен исходному; для CompletelyInside — -1.

Важно сохранять порядок float-операций. Проекция использует
`dot(point - normal*distance, normal)`, а не алгебраически упрощённое выражение.
Это влияет на точное совпадение новых координат с оригиналом.

## Работа с памятью

Исследовательский `BrushMemoryView` — четыре указателя, три счётчика и три
ёмкости; на x86_64 размер 56 байт. Буферы принадлежат вызывающему коду.
`edgeChunkCapacity` задаётся блоками по четыре записи для каждого массива рёбер;
проверка добавления сохраняет исходную формулу запаса `(edgeCount + added + 4)/4`.

**Рост памяти пока не реализован.** Оригинал вызывает Set*Capacity, а этот модуль
требует заранее выделенного запаса. C++ сообщает исчерпание через length_error;
исследовательские C-обёртки возвращают -2 для вставки/деления кольца и 255 для
SplitByPlane. Операции не транзакционные: ошибка может оставить частичные изменения.
Это ограничение адаптера памяти, а не восстановленное поведение оригинального ядра.
Входные индексы и топология должны быть корректными, как у внутренних функций.

## Проверки против оригинального машинного кода

```sh
cmake -S native -B /tmp/realtime-csg-recovery/build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build /tmp/realtime-csg-recovery/build
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
python3 -B tools/compare_recovered_splitting.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 2000
```

Дифференциальная проверка поддерживает Linux x86_64. Она явно исполняет только
просмотренные геометрические функции оригинала на буферах с большим запасом
ёмкости. Функции оригинального распределения памяти не отображаются и не вызываются.
Границы копируемых инструкций проверены по дизассемблеру; SHA-256 фиксирован.

Для каждого вызова сравниваются возврат, выходной ID, счётчики и **все байты**
четырёх буферов, включая неиспользуемые записи с одинаковым начальным заполнением.
Это обнаруживает лишние записи и отличия нетронутых полей, а не только форму меша.
Дополнительно проверяются кольца, обратные связи, владельцы, twin и их концы,
диапазоны индексов и отсутствие потерянных рёбер.

Результат GCC 16.2.1, seed 1559:

- 2 000 вставок вершины;
- 2 000 разделений кольца, включая одинаковый vertex ID на границах;
- 2 000 разрезаний полигонов с разными масштабами, касаниями, проходом через
  вершину/ребро, совпадающими плоскостями, тонкими полигонами и близкими пересечениями;
- 756 дополнительных вызовов разрезания в последовательностях по 12 операций
  на замкнутых повёрнутых коробках с разными размерами по осям;
- расхождений возвратов, ID и байтов буферов нет.

Самостоятельный CTest проверяет два разрезания поверхности куба, сохранение
суммарной площади, топологии, surfaceIndex и исходной семантики flag-байта.
Два CTest-теста также прошли сборку с AddressSanitizer/UndefinedBehaviorSanitizer
(проверка утечек выключена; тесты относятся к работе с заранее выделенными буферами).

Эти результаты относятся к перечисленным функциям и набору входов. Булевы операции
целых brushes, генерация финального треугольного меша, вызовы Unity и совместимость
с Windows DLL пока не реализованы/не проверены. Правила дерева и программы
видимости теперь описаны в [модуле категоризации](categorization.ru.md).
Далее требуется подготовка категорий фрагментов по плоскостям объёмных brushes,
затем триангуляция.
