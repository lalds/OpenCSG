# MergeBrushIndices: массивы произвольной длины

Реализация `mergeBrushIndices` находится в
`native/recovered/brush_edge_cleanup.cpp`; C ABI —
`rcsg_recovered_merge_brush_indices`. Парный helper использует тот же алгоритм.
Источник: macOS x86_64 RealtimeCSG 1.559,
`MergeBrushIndices`, `0x3218e..0x32a76`, SHA-256
`26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.
Эквивалентность Windows DLL не проверена.

## Порядок обработки

Непустой массив содержит живые индексы групп или `-1`. Оригинал сортирует
весь массив по убыванию, исключает хвостовые `-1` из активной длины,
возвращается досрочно для пустого набора или одинаковых индексов.
При нескольких разных индексах разворачивает активный префикс.
Повторы удаляет заменой из активного хвоста с повторным поиском;
получающийся порядок не обязан оставаться возрастающим.
Неиспользуемые элементы массива сохраняют следы этих операций.

Минимальный индекс становится root. Surface refs добавляются в порядке
оставшихся индексов с чувствительным к числу повторов сопоставлением,
описанным в [парном варианте](merge-brush-pair.ru.md).
Геометрия, triangle list и connection list root сохраняются.
Удаление использует комбинацию обрезания хвоста и перестановки последней
группы в удаляемый слот. Mapping записывается при каждом удалении,
затем применяется к исходным тегам треугольников один раз.

Mapping не композирует последовательные перестановки. Например, при четырёх
группах массив `[0,0,1,2]` превращается в `[0,2,1,2]`, остаются две группы,
а исходные теги `[0,1,2,3]` становятся `[0,0,1,2]`.
Последний тег выходит за новый диапазон: это воспроизведённое поведение
оригинала, подтверждённое исполнением исходной функции, а не обещание
корректного конечного меша. Для интеграции потребуется отдельное решение
о нормализации таких результатов.

## Граница безопасного воспроизведения

Некоторые порядки после удаления повторов приводят к обращению к уже
уничтоженному слоту исходного вектора. Пример: четыре группы,
`[0,1,1,2,3]`. Это следует из порядка удаления и деструктора группы,
освобождающего её списки без обнуления указателей. Такие входы намеренно
не исполняются на оригинале; падение оригинала экспериментально не заявляется.
Открытая реализация обнаруживает обращение за текущий размер и возвращает
ошибку без изменения переданных буферов.

Работа выполняется на временных копиях. Ёмкости проверяются до записи;
при ошибках сохраняются mesh, группы, списки, массив индексов, groupCount
и selectedIndex. Владение выделениями не пересекает C ABI.
Коды: `0` — успех, `-1` — недопустимый вход или порядок удаления,
`-2` — недостаточная ёмкость, `-3` — прочая ошибка.
Нулевой размер входного массива отвергается.

## Проверка

`tools/compare_merge_brush_indices.py`, seed 1559, 5 000 наборов,
длины от 1 до 32, от 0 до 16 групп:

- 3 504 исполнения исходной функции; 40 873 сравнённых элемента массива;
- 2 696 случаев с фактическим объединением;
- 1 496 отклонённых порядков с обращением к уничтоженному слоту;
- ноль расхождений результата, массива индексов, всех байтов треугольников,
  геометрии и содержимого трёх списков активных групп.

Для отклонённых входов проверяются ошибка и неизменность состояния,
а не эквивалентность неопределённому поведению оригинала.
У входных списков есть запас ёмкости; исходный путь их роста здесь не покрыт.
Дополнительно повторены 5 000 сравнений пары и 5 000 полных
CleanUpBrushEdges с конфликтами — без расхождений.
CTest парного helper расширен массивами с повторами, несколькими хвостовыми
удалениями, исходным некомпозированным mapping и атомарным отказом.
Все 14 CTest проходят в обычной сборке и с ASan/UBSan
(`ASAN_OPTIONS=detect_leaks=0`).

```sh
python3 tools/compare_merge_brush_indices.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000
```

Полная Create/Optimize, интеграция в Unity и работоспособность всего плагина
этой проверкой не установлены.
