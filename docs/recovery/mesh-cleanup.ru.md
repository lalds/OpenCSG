## CleanUpRemovedVertices

В оригинальном OptimizationContext списки удалённых triangles и vertices
находятся по +24 и +72, каждый в формате libc++ vector. Новый интерфейс
принимает два массива индексов напрямую. Вызывающий код должен заранее
пометить удалённые triangles отрицательным surfaceIndex и переподключить
остающиеся triangles так, чтобы они не ссылались на удалённые vertices.

Функция:

1. Создаёт карты старых индексов, помечая удалённые значением -1.
2. Сортирует списки удалений и переносит живые записи с хвоста в освободившиеся места.
3. Пересчитывает индексы vertices в живых triangles.
4. Уплотняет triangles, сохраняя все байты их записей.
5. Обновляет ссылки vertices и triangle twins; ссылки на удалённые triangles
   делает недействительными. Затем заново записывает ссылки vertices на рёбра.

Ёмкости буферов не меняются; хвостовые старые записи не обнуляются.
Функция не принимает геометрических решений об удалении, не сваривает вершины
и не исправляет T-стыки. Удаление вырожденного треугольника без предварительной
перестройки соседства само по себе может оставить отверстие.
Уплотнение выполняется до подготовки world positions и межbrush связей:
эти более поздние поля здесь не пересчитываются.

Новый интерфейс заранее проверяет индексы, повторные удаления и оставшиеся
ссылки. Ошибки входа отклоняются до мутации. Выделение памяти карт происходит
также до изменений. Требуется корректная исходная топология; проверки здесь
не заменяют полную валидацию произвольного внешнего меша.

### Особый путь счётчика vertices

В исходном коде переход `0x32d5f → 0x32daf` обходит вычитание числа удалённых
vertices из счётчика. Это происходит при исчерпании поиска живой записи
с хвоста, в том числе для некоторых входов, где немного живых записей уже
перенесено в нижние свободные места. Поведение подтверждено выполнением
оригинала на синтетических входах и сохранено в восстановленной функции.
Какие дополнительные ограничения накладывают оригинальные вызывающие функции
на такие списки, пока не установлено.

`compactVisibleTriangles` — **новый экспортный адаптер**. Он копирует меш,
помечает скрытые state=1 triangles, находит неиспользуемые vertices и вызывает
восстановленное уплотнение. Итоговый размер vertices задаётся по известному
числу используемых записей независимо от указанного особого пути.
Полностью пустой результат возвращается отдельно. Вход остаётся неизменным.
Межbrush связи сбрасываются: после перенумерации их нужно построить заново.
Состояния 2/3, направления, нормали и surfaceIndex сохраняются.
Почти нулевые треугольники этим адаптером не удаляются.

## ConnectGaps и уточнение TriangleRecord

Байты TriangleRecord +72..+95 — три записи по восемь байт:
`{ int32 brushIndex; uint32 triangleEdge; }`. Теперь поле называется brushEdges.
Оставшиеся +96..+107 пока неизвестны. Общий размер TriangleRecord — прежние
116 байт; ранее восстановленные смещения не изменились.

ConnectGaps обходит triangles с допустимым surfaceIndex и по каждой такой
межbrush ссылке записывает в целевой triangle обратную пару
`{исходный brushIndex, (исходный triangleIndex << 2) | corner}`.
Отсутствующие, отрицательные, выходящие за размер manager или устаревшие узлы
пропускаются. Сравнение nodeIndex с индексом слота подтверждено по `0x3a2e3`.
Порядок записей важен: вход может содержать циклы, ссылки на тот же меш
и несколько записей в один целевой слот.

Оригинал читает глобальный массив указателей узлов по `0x404f8/0x40500`,
nodeIndex по node+24, mesh по brush+96, число surfaces по surfaces+40.
Новый интерфейс принимает явный manager из GapBrushView. Активные неверные
ссылки на рёбра отклоняются до записи вместо unchecked-доступа оригинала.
Для непустого входа исходный ID должен идентифицировать переданный меш.

Это **только обратное связывание уже найденных соответствий**. Оно не сравнивает
позиции, не обнаруживает T-стыки и не создаёт совпадающие разбиения рёбер.
Исходная FixGaps сначала очищает brushEdges, затем анализирует интервалы
и вызывает SplitTriangleEdgeIndex. Разбиение ребра уже восстановлено;
сбор интервалов также [восстановлен и связан с разбиением](gap-intervals.ru.md).
Выбор межbrush-соседей и полный обход ещё впереди.

## Проверки

```sh
cmake --build /tmp/realtime-csg-recovery/build
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
python3 -B tools/compare_recovered_mesh_cleanup.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000
/tmp/realtime-csg-recovery/build/recovered_convex_csg_tests /tmp/realtime-csg-recovery/demo
```

Эталон запускает изолированные байты функций, конструктора vector<int> и его
allocate на Linux x86_64. SHA-256 проверяется, страж статической инициализации
подготовлен. new/delete/bzero перенаправлены в Linux libc; импорт libc++ сортировки
int заменён сортировкой знаковых int32. Эта замена явно отделена от геометрии.
Не исполняются Unity, инициализаторы Mach-O и пути исключений. Код RX, данные RW,
RWX-страниц нет. Скрипт следует запускать отдельным процессом.

При seed 1559: 5 000 уплотнений и 5 000 ConnectGaps, расхождений нет.
Сравниваются все байты массивов triangles/vertices, счётчики, ёмкости, неизвестные
указатели и отсортированные списки. Есть пустые массивы, удаление хвостов,
несколько дыр, все удалённые записи, мёртвые соседи, stale/null manager nodes,
недопустимые surfaces, самоссылки и перезапись одного целевого слота.

Все 740 объёмных результатов теперь проверяются после compactVisibleTriangles:
сохранение объёма/площади, нормалей, surfaceIndex, правильности живых twins
и ссылок vertices. До фильтрации отдельно проверяется замкнутость каждого
исходного brush. После неё допускаются граничные рёбра между исходными телами.
Неиспользуемых vertices в экспортном результате нет; OBJ используют новые индексы.
Все восемь CTest проходят также ASan/UBSan с отключённым leak detection.

Следующее существенное звено — полный обход и выбор соседей в FixGaps.
Разбиение TriangleEdgeIndex уже восстановлено и проверено отдельно.
Пока не установлена полная эквивалентность Optimize/FixGaps,
и объединённый выход не гарантирован как сваренный manifold-меш.
