# Второй проход и совместный Optimize

Перенесён `TriangleMesh::RemoveVertexOnEdgeBetween2Surfaces`, macOS x86_64
RealtimeCSG 1.559, `0x339fe..0x34c44`. Собрана последовательность обоих проходов
из `Optimize` (`0x34c44`, вызовы по `0x34cf1` и `0x34d06`).
SHA-256 источника:
`26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.
Поведение Windows DLL и запуск в Unity этим не проверены.

Реализация: `two_surface_decisions.cpp`, `two_surface_pass.cpp` и общий
транзакционный слой `plane_vertex_pass.cpp`. Интерфейс:
`native/include/realtimecsg/recovered_mesh_optimization.h`.

## Последовательность второго прохода

1. Очищаются размеры removedTriangles/removedVertices; исходные вершины
   посещаются по убыванию индекса. Временные добавленные вершины не становятся
   отдельными итерациями внешнего обхода.
2. Выполняется [отбор двух областей](two-surface-candidates.ru.md).
3. Для обоих граничных twins проверяются surface/state соответствующей
   противоположной области и общие индексы концов ребра. Flags не сравниваются.
   Проверяется, что сосед не совпадает со своим исходным треугольником.
4. Если оба соседа являются исходной парой, сразу вызывается
   [RemoveVertexInMiddleOfPlane](plane-vertex-removal.ru.md).
5. Иначе проверяется геометрия `u=C-Y`, `v=X-C` относительно плоскости первой
   области. Короткие векторы допускаются. Если квадрат cross меньше
   `9.999999439624929e-11f`, отношение `dot(u,v)/(dot(u,u)*dot(v,v))` за любым
   из порогов ±`0.9999998807907104f` пропускает проверку ориентации.
   Здесь отрицательный край отличается от [Swizzle](swizzle.ru.md).
   В остальных случаях нужен `dot(cross,normal) >= cross²*9.999999747378752e-6f`;
   unordered comparison отклоняется. Плоскость в исходнике читается до проверки cross.
6. Когда одна из областей состоит из одного треугольника, выбирается Swizzle
   следующего угла соответствующего twin. При успехе заново рассматривается
   та же исходная вершина, начиная с её обновлённого handle.
7. Иначе добавляются два временных треугольника и копия вершины. Обе области
   повторно обрабатываются helper удаления. В конце всего прохода вызывается
   [CleanUpRemovedVertices](mesh-cleanup.ru.md).

`planTwoSurfaceVertex` отдельно возвращает отказ или план RemoveInPlane,
Swizzle, Split. Он не выделяет память меша и не меняет вход. Выбранный Swizzle
ещё может отклониться внутри собственного геометрического helper.

## Временное разделение

Пусть A/B — граничные handles, TA/TB — их twins, C — общая вершина,
X/Y — предыдущие вершины A/B. Добавляются:

| Поле | Первый новый треугольник N | Второй новый треугольник M |
| --- | --- | --- |
| vertices | Y, C, X | X, C, Y |
| twins | M:0, TB, A | N:0, TA, B |
| normals | TB:corner, A:corner, A:previous | TA:corner, B:corner, B:previous |
| surface/state/flags | область A | первый треугольник области B |

Последний и первый треугольники области B могут иметь разные flags:
отбор сравнивает лишь surface/state. Это различие сохранено.
Четыре исходных edgeSource объединяются общим MergeBrushIndices **до**
увеличения triangleCount. Затем выбранный тег записывается во все шесть
новых углов и четыре исходных граничных угла. Восстанавливаются backlinks.
Неизвестные поля новых записей сохраняют байты свободных слотов.

Исходная вершина получает handle M:1, её копия — N:1 и ту же позицию.
Область копии обходится через `twin(next(h))`, с заменой vertex index на индекс
копии. Это другой шаг обхода, чем `previous(twin(h))` при отборе кандидата.
Сначала вызывается удаление копии, затем исходной вершины; bool обоих вызовов
игнорируется. Удаление может отказать после изменения scratch-списков или
вернуть false после изменения самого меша — исходное поведение сохранено.

Неоднозначность регистра handle копии из раннего разбора разрешена:
по `0x34990..0x34993` r11d заново устанавливается в N:1. Его значение после
вызова MergeBrushIndices не используется как окончательный handle.

## Переносимый API и атомарность

- `rcsg_recovered_remove_two_surface_vertices`: только второй проход.
- `rcsg_recovered_optimize_mesh`: первый проход с уплотнением, затем второй
  с повторным уплотнением, на общем рабочем context.

Оба возвращают 0 при успехе, -1 при некорректных views/топологии,
-2 при нехватке ёмкости и -3 при прочих ошибках. В общем Optimize одна
транзакция охватывает оба прохода: поздняя ошибка второго откатывает и первый.
Mesh, шесть context-списков, три вида group storage и groupCount коммитятся
только в конце. После перестановок групп возвращаются исходные caller-owned
pointers, включая retired slots с нулевыми размерами.

В отличие от native, буферы имеют фиксированную ёмкость. Для каждого реального
Split нужны ещё два triangle slots и один vertex slot; удалённые записи
освобождаются только при итоговом уплотнении. Native предварительно растит
ёмкости даже перед некоторыми последующими отказами. Эта политика резервирования
не воспроизводится, ownership не передаётся через API. Context тоже должен
иметь достаточную ёмкость. Ограничения безопасных порядков общего
[MergeBrushIndices](merge-brush-indices.ru.md) остаются в силе.

Изменяемые буферы должны быть раздельными. World/gap-буферы не пересчитываются:
Optimize предназначен для этапа перед их построением. Добавлены границы обхода
для malformed циклов, вместо возможного бесконечного цикла исходника.

## Сравнение с оригиналом

`tools/compare_two_surface_decisions.py`: 5 000 входов, seed 1559;
3 972 отказа, 84 выбора RemoveInPlane, 281 Swizzle, 663 Split; все девять
пар граничных углов, 270 действий при одной поверхности с разными состояниями,
ноль расхождений. Здесь перехвачены четыре выхода перед исполнением действий;
это ограниченная проверка решений, а не полная проверка мутаций.

`tools/compare_two_surface_pass.py` выполняет неизменённый исходный код:

| Режим, 5 000 входов каждый | Уменьшение числа треугольников | Уменьшение vertexCount | Удалено групп |
| --- | ---: | ---: | ---: |
| Второй проход | 34 096 | 17 048 | 979 |
| Оба прохода последовательно | 74 038 | 36 607 | 1 111 |
| Исходная обёртка Optimize | 74 942 | 37 117 | 1 092 |

Во всех режимах — ноль расхождений полных mesh buffers, включая свободную
ёмкость, metadata/counts и активных групп с их тремя списками.
В первых двух режимах также побайтно сравниваются все шесть context-векторов,
включая хвосты. В режиме `--original-wrapper` исходный Optimize сам выделяет,
увеличивает и уничтожает свои шесть векторов: его уничтоженный context
**не сравнивается** с portable context. Сравниваются mesh/groups после возврата.
Host-callback заменяет внешний libc++ sort знаковых int; выделения/освобождения
отслеживаются. Полные проходы не используют перехватов из prefix-oracle.

Наборы: замкнутый grid-top с пирамидальной нижней частью и объединёнными
копланарными боковыми поверхностями, открытые grid, смешанные surface/flags,
двухвершинные компоненты, пустые входы, повороты/масштабы, перестановки индексов
и углов. В каждом прогоне 625 пустых входов, 3 125 наборов с замкнутой grid-компонентой;
возможные дополнительные открытые компоненты не делают весь mesh замкнутым.
Полные вызовы здесь используют 0..2 группы; общий merge с большим числом групп
проверяется своим отдельным oracle. Входы режимов различаются из-за порядка
потребления RNG, поэтому различие их сумм не означает различие реализаций.

После рефакторинга общий первый проход повторно прошёл прежние 5 000 сравнений:
36 108 удалённых треугольников, 18 054 уменьшения vertexCount, без расхождений.

## Геометрический тест и дальнейшая интеграция

21-й CTest использует замкнутую верхнюю сетку 3×3 с четырьмя боковыми поверхностями.
Второй проход удаляет восемь промежуточных вершин стыков: 30→14 треугольников,
17→9 вершин. Оба прохода дают 6 треугольников и 5 вершин. Во всех случаях
объём 3 сохраняется, twins действительны и взаимны.

Проверены откат после Split/merge при нехватке scratch-ёмкости, восстановление
caller-owned group pointers, отказ при нехватке временных triangle slots,
а также откат первого прохода при позднем исчерпании ёмкости во втором.
Все 21 CTest проходят обычную сборку и ASan/UBSan (`detect_leaks=0`).

```sh
python3 tools/compare_two_surface_decisions.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000
python3 tools/compare_two_surface_pass.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000
python3 tools/compare_two_surface_pass.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000 --both-passes
python3 tools/compare_two_surface_pass.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000 --original-wrapper
```

Это восстановленная последовательность Optimize на проверенных индексированных
входах и с явными переносимыми буферами. Теперь она включена в [исследовательскую подготовку выпуклых мешей](convex-mesh-preparation.ru.md)
вместе с source groups и их итоговой очисткой. Подключение общего scene manager,
foreign connections и gap repair требует дальнейшей работы с transforms
и исходными особенностями remap/self-connections.
Готовность полной сцены, Unity ABI и функций редактора этим не заявляется.
