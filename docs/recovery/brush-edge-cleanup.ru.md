# CleanUpBrushEdges: группы и списки треугольных рёбер

В `native/recovered/brush_edge_cleanup.cpp` перенесён CleanUpBrushEdges,
включая объединение конфликтующей пары через восстановленный
[MergeBrushIndices с count=2](merge-brush-pair.ru.md). Интерфейс находится в
`native/include/realtimecsg/recovered_brush_edge_cleanup.h`;
C-функция — `rcsg_recovered_cleanup_brush_edges`.

Источник — Mach-O x86_64 RealtimeCSG 1.559, SHA-256
`26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.
Оригинальная функция: `0x34f7c..0x357c7`, включая вызываемые vector helpers.
Полное тело с обработкой исключений оканчивается перед `0x35840`.

## Место в конвейере

Create переносит EdgeLink+4 в `TriangleRecord::edgeSource[corner]`
по `0x30e8e..0x30ea2`, но не получает vector<BrushEdge> и не заполняет его
списки triangle handles. Это делает последующий CleanUpBrushEdges.
Перенос source indices уже присутствовал в новом `triangulateConvexBrush`;
теперь добавлено согласование/уплотнение групп и заполнение их списков.

Таким образом, для поддерживаемого случая проходит исследовательская цепочка
`FindBrushEdges → triangulateConvexBrush → cleanUpBrushEdges`.
Отдельно перенесён [Create с подготовкой вырожденных контуров](mesh-creation.ru.md);
адаптер теперь использует этот проход на временной копии входа.

## Объединение конфликтующих групп

Для каждой помеченной стороны нужен корректный взаимный triangle twin.
Если назначенные индексы различаются, исходная функция вызывает
`MergeBrushIndices` по `0x35017`, очищает и переназначает группы в более широком
проходе. Эта ветвь теперь перенесена для двух действующих индексов.
Для других стадий добавлен [вариант с массивами индексов](merge-brush-indices.ru.md),
сохраняющий исходный порядок операций на путях с живыми слотами групп.

## Восстановленные этапы

### Согласование сторон, `0x34fa8..0x35056`

Треугольники обходятся по порядку, corners 0–2. Назначенный индекс переносится
на twin, если у twin индекс -1. Существующие равные индексы сохраняются.
Теги за пределами массива групп допускаются на этом шаге, если не вызывают
конфликта: оригинал нормализует их позже.

### Фильтр видимости, `0x3505e..0x35144`

У видимого треугольника (`flags & 8`) tag удаляется, если twin тоже видим.
У скрытого треугольника исходная ветвь по `0x35082..0x350ae` фактически
сохраняет tag: единственная запись -1 выполняется в поле twin, которое уже -1.
Поэтому hidden/hidden пары в этом бинарнике могут сохранять группы.
Это поведение воспроизведено и проверено исполнением, без предположения
об эквивалентности Windows DLL.

### Подсчёт и уплотнение, `0x3514a..0x35636`

Индекс вне `[0,oldGroupCount)` заменяется на -1. Для каждого существующего
индекса подсчитываются все triangle corners, включая скрытые.
Группы с нулевым числом использований удаляются обменом с последней группой.
Проверка той же позиции повторяется, пока в ней не окажется используемая
группа или массив не закончится. Стабильная сортировка здесь не применяется.

Вместе перемещаются surfaceRefs, triangle handles, connections, пара surfaces
и line record. Таблица old→new remap строится с исходным порядком обменов.
Исходная функция освобождает удалённые vectors. Переносимый API сохраняет
caller-owned буферы удалённых слотов и обнуляет только их counts.
Активная часть массива и её содержимое совпадают с оригиналом.

### Заполнение списков, `0x35636..0x35748`

Теги surviving triangles заменяются remap-индексами. Каждый действующий tag
добавляет handle `(triangleIndex << 2) | corner` в соответствующий список.
Порядок — triangle index, затем corner 0–2. Список включает обе стороны
помеченного ребра; устранения twins здесь нет.

Существующие списки не очищаются. Повторный вызов может добавить те же handles
снова. Для обычного первичного прохода после FindBrushEdges их counts равны нулю.
SurfaceRefs и connections не пересчитываются, а только перемещаются с группой.

## Переносимые проверки и память

Перед записью новый интерфейс моделирует изменения тегов и remap во временной
памяти, проверяет пары, views и ёмкости всех surviving списков.
При неверном входе возвращается -1, при нехватке ёмкости — -2.
Вход остаётся неизменным при ошибках. Это дополнительная гарантия bounded API;
оригинал полагается на внутреннюю согласованность и динамические vectors.
Изменяемые views и буферы должны быть независимыми, принадлежать вызывающему коду.
Геометрия, triangle twins и все поля треугольников вне edgeSource не меняются.

## Исполнение оригинала и сравнение

`tools/compare_brush_edge_cleanup.py` вызывает полный неизменённый
CleanUpBrushEdges. Без --merges входы не требуют MergeBrushIndices;
с --merges генерируются конфликтующие назначенные индексы.
Загружается тело функции и его зависимости по локальному аудиту символов;
SHA-256 проверяется. Код RX, данные RW. Для исходного stack protector задан
локальный guard; аллокаторы и операции памяти привязаны к Linux libc.

Группы оригинала содержат три реально выделенных через host malloc vectors,
так что удаление и перестановка групп выполняют исходные deallocate/destructors.
Их выделения/освобождения проверяются обёртками. Triangle lists имеют запас
ёмкости для добавления handles; рост этого буфера в данной проверке исключён.

При seed 1559:

| Показатель | Результат |
| --- | --- |
| Входы без MergeBrushIndices | 5 000 |
| Удалённые группы | 17 539 |
| Записи в итоговых triangle lists | 152 287 |
| Сохранённые hidden/hidden теги | 40 808 |
| Расхождения | 0 |

Сравниваются полные triangle buffers и все поля активных групп:
surfaceRefs в исходном порядке, triangle lists, connections, surface pair,
direction и origin. Количества групп сравниваются отдельно.
Покрыты пустые меши/группы, односторонние теги, отрицательные/завышенные
индексы, видимость, удаление нескольких пустых хвостов подряд,
перестановки групп, непустые исходные списки и произвольные прочие поля.
Тестовые twins взаимны; данные не обязаны описывать геометрически замкнутый
объём, поскольку этот проход не читает координаты.

Тринадцатый CTest проверяет порядок уплотнения и списков, сохранение метаданных,
повторное добавление handles, видимость, нормализацию индексов, обработку
конфликтов через объединение и ошибку ёмкости до мутации. Интеграционный пример создаёт группы
на двустороннем полигоне с коллинеарными сегментами, триангулирует его
восстановленным fan-проходом и получает списки на 4 и 2 triangle handles.
Проверяются соответствие tag↔list и взаимность triangle twins.

Все 14 CTest проходят в обычной сборке и с ASan/UBSan
(`ASAN_OPTIONS=detect_leaks=0`).

```sh
cmake --build /tmp/realtime-csg-recovery/build
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
python3 -B tools/compare_brush_edge_cleanup.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000
```

Следом нужны Optimize, интеграция полного конвейера и решение
наблюдаемой адресации FindConnections. Полная автоматическая обработка
произвольной CSG-сцены и Unity ABI пока не реализованы.
