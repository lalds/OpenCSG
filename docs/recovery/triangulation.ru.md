# Восстановленная триангуляция выпуклых полигонов

Реализация — `native/recovered/triangulation.cpp`, интерфейс —
`native/include/realtimecsg/recovered_triangulation.h`.
Восстановлены две функции из Mach-O x86_64:

| Функция | Адреса |
| --- | --- |
| TriangleMesh::TriangulateConvexPolygon | `0x2f4d4..0x2f820` |
| CSGCategorizationStack::FlagInvisiblePolygons | `0x208d4..0x2094e`, таблица переходов `0x20950` |

Источник имеет SHA-256
`26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.
Это восстановление вычислений и записей в память, с новым переносимым интерфейсом
и проверками входа/ёмкости. Воспроизведение оригинального управления памятью
и его libc++ vector не входит в интерфейс.

## Формат записей

`TriangleEdgeIndex` занимает четыре байта: `(triangleIndex << 2) | corner`.
Низкие биты 3 означают недействительную ссылку. Оригинальный статический
InvalidIndex после инициализации преобразуется в `0xffffffff`.

Вершина TriangleVertex — 16 байт: ссылка на ребро по +0, позиция Vector3 по +4.
Частично восстановленный TriangleMesh занимает 48 байт на x86_64:
указатели на треугольники +0 и вершины +8; worldPositions +16 и worldVertexLookup +24
(уточнены при [разбиении рёбер](triangle-splitting.ru.md));
числа треугольников/вершин +32/+36, ёмкости +40/+44.

Треугольник занимает 116 байт:

| Смещение | Поле |
| --- | --- |
| +0 | Три индекса вершин, int32 |
| +12 | Три ссылки на соседние рёбра, uint32 |
| +24 | Три Vector3 нормали углов |
| +60 | Три int32 атрибута рёбер; сначала -1 |
| +72 | Три пары brushIndex/triangleEdge, по 8 байт; уточнено при восстановлении ConnectGaps |
| +96 | 12 неизвестных байт |
| +108 | Индекс исходной поверхности, int32 |
| +112 | Флаги, uint8 |
| +113 | Неизвестный байт, функция его не меняет |
| +114 | Состояние категоризации, 16 бит |

Назначение нормалей подтверждается вызывающим Create: по `0x30cb8..0x30cde`
из поверхности читаются xyz нормали, затем по `0x30d6b..0x30d8b` копируются
для каждого угла. Внутри TriangulateConvexPolygon эти значения только копируются;
проверка использует также произвольные float-биты, включая NaN.
Атрибуты рёбер вызывающий Create заполняет из второго int поля EdgeLink
по `0x30e8e..0x30ea2`. При последующем восстановлении FindBrushEdges
подтверждено, что это индекс исходной группы BrushEdge (`edgeSource`).

## Алгоритм и связи

Для углов `v[0..n-1]` создаются `n-2` треугольника:
`(v0,v1,v2)`, `(v0,v2,v3)`, …, `(v0,v[n-2],v[n-1])`.
У ребра с номером c конец — вершина c, начало — вершина `(c+2)%3`.
Внутренние диагонали связываются друг с другом; граничные рёбра — с ранее
созданными соседями, переданными вызывающим кодом. Обратные ссылки соседей
и ссылка вершины на одно из её рёбер тоже обновляются.

Порядок вывода граничных ссылок соответствует исходному контуру:
последний треугольник, ребро 0; первый треугольник, ребро 1;
затем ребро 2 каждого треугольника по очереди.
Нормали, surface, flags и state переносятся из входа. Неизвестные поля
и неиспользованная ёмкость остаются нетронутыми.

В этой функции **нет** проверки площади, удаления коллинеарных/совпавших вершин
или выбора диагонали по качеству. Нулевая площадь отдельных треугольников
сохраняется, как в оригинале. Позднейший Optimize ещё не восстановлен;
[FixGaps](gap-dispatch.ru.md) перенесён на проверенном домене.

Исследовательская функция отклоняет меньше трёх углов, неверные индексы и ссылки
на ещё не существующих соседей. Предварительная проверка ёмкости позволяет
вернуть ошибку до изменения буферов. Оригинальный SetTriangleCapacity не исполняется.

## Флаги видимости

FlagInvisiblePolygons сохраняет старшие два бита flags и заменяет младшие
по **знаковому** 16-битному состоянию. По таблице переходов и исполнению:

| State | Новые младшие 6 бит flags |
| --- | --- |
| 1 | `0x00` |
| 2 | `0x09` |
| 3 | `0x1a` |
| 4 | `0x03` |
| Остальные, включая 0 и отрицательные | `0x29` |

Состояния исследовательского компилятора: 1 скрыто, 2 обычное направление,
3 обратное. Смысл специального состояния 4 в полном конвейере пока не установлен.
Функция только выставляет флаги; она не разворачивает индексы или нормали.

## Проверка на оригинальном коде

```sh
cmake -S native -B /tmp/realtime-csg-recovery/build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build /tmp/realtime-csg-recovery/build
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
python3 -B tools/compare_recovered_triangulation.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000
```

Скрипт запускает только байты двух проверенных функций на Linux x86_64.
Перед исполнением сверяется SHA-256, статический guard установлен в завершённое
состояние, буферы заранее выделены; импорты guard/allocator не отображаются.
Код имеет RX-защиту, данные — R; RWX-страниц нет. Unity и инициализаторы Mach-O
не запускаются. Сравнение следует запускать отдельным процессом.

При seed 1559 проверены 5 000 полигонов с 3..64 углами и 158 377 созданных
треугольников. В 4 705 случаях были существующие соседи. Сравниваются все байты
массивов треугольников, вершин, выходных граничных ссылок и счётчики. Начальные
буферы заполнены случайными байтами, поэтому видны лишние записи и обнуления.
Для флагов перебраны все 65 536 битовых представлений состояния с каждым из
четырёх сочетаний сохраняемых старших битов: 262 144 проверки. Расхождений нет.

Самостоятельный CTest проверяет фиксированный контур с коллинеарными вершинами,
соседство, метаданные и отсутствие частичных изменений при ошибках.
Все восемь CTest проходят обычную сборку и ASan/UBSan без leak detection.

## Подключение к объёмному проходу

`triangulateConvexBrush` — **новый адаптер** исследовательского конвейера.
После восстановления [всей функции Create](mesh-creation.ru.md) он вызывает
её на копии исходных Polygon/HalfEdge и выставляет восстановленные флаги видимости.
Он обрабатывает также скрытые фрагменты, сохраняя замкнутую топологию каждого
исходного brush. Для экспорта видимых state=3 индексы разворачиваются.
При использовании записанных нормалей рендерер должен развернуть и их.

Прежние 740 интеграционных результатов теперь проверяются по настоящему выходу
этого адаптера, затем [уплотнения видимого меша](mesh-cleanup.ru.md): объём,
площадь, направление, ссылки на поверхности и симметрия живых triangle twins.
До фильтрации также проверяется замкнутость исходных тел. OBJ-примеры содержат
треугольники, а не n-gon грани:

```sh
/tmp/realtime-csg-recovery/build/recovered_convex_csg_tests /tmp/realtime-csg-recovery/demo
```

Create и обработка двухрёберных вырождений теперь восстановлены отдельно.
[TriangulateConcavePolygon перенесён отдельно](concave-triangulation.ru.md)
для следующей стадии оптимизации; в исследованном Create он не вызывается.
Не восстановлены полный Optimize, UV/материалы, общая межbrush сварка и Unity ABI.
CleanUpRemovedVertices и обратное связывание ConnectGaps уже восстановлены.
Ссылки внутри каждого исходного brush не означают сварку окончательного CSG-меша:
после удаления скрытых граней соседняя видимая поверхность может принадлежать
другому исходному телу. Именно эту связь нужно восстановить на следующем этапе.
