# TriangulateConcavePolygon: вырезание ушей с повторным использованием записей

Перенесена `TriangleMesh::TriangulateConcavePolygon`, macOS x86_64
RealtimeCSG 1.559, `0x2f822..0x30409`, вместе с вычислениями
`IsPointInTriangle`, `0x30409..0x30810`.
SHA-256 источника:
`26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.
Исходный вызов из RemoveVertexInMiddleOfPlane находится по `0x31d67`.
В исследованном Create эта функция не вызывается.
Windows-поведение пока не проверено.

Реализация — `native/recovered/concave_triangulation.cpp`;
интерфейс добавлен в `recovered_triangulation.h`.

## Выбор уха

Для каждого размера контура n>3 перебираются тройки последовательных углов
в порядке `(n-2,n-1,0)`, `(n-1,0,1)`, `(0,1,2)`, … .
Для позиций a,b,c вычисляются u=b-a, v=c-b, cross=u×v и
качество `|cross|²/(|u|²*|v|²)`. Выбирается допустимая тройка со строго
наибольшим качеством; при равенстве сохраняется первая.

Первый проход пропускает короткие стороны с квадратом длины
`<=3.6000002978653356e-7`. При малом cross² (`<9.999999439624929e-11`)
дополнительно проверяется ratio `dot(u,v)/(|u|²*|v|²)`: нижняя граница
`-0.9999998807907104` отклоняет тройку, верхняя `0.9999998807907104`
разрешает её без проверки ориентации. В остальных случаях требуется
`dot(cross,planeNormal) >= |cross|²*9.999999747378752e-6`.
В ratio оригинал не использует квадратный корень.

Если допустимых ушей нет, повторяется проход, в котором короткие стороны
разрешены с качеством 0 и без проверки остальных точек.
Если и он ничего не выбрал, оригинал использует углы 0,1,2.
Последние три угла используются напрямую, без геометрических проверок.
Следовательно, helper сам по себе не гарантирует качественный или корректный
результат для самопересекающегося контура, неверной нормали или NaN.

## Проверка остальных точек

IsPointInTriangle фактически проверяет, есть ли среди перечисленных вершин
другая точка внутри расширенного треугольника. Совпадение с a/b/c исключается
по индексу вершины, а не по её позиции или позиции угла в массиве.

Для каждой стороны строится плоскость по выражению
`cross(edge, edge+planeNormal)`. Это выражение сохранено буквально:
алгебраическая замена на cross(edge,planeNormal) изменила бы округление.
Компоненты cross вычисляются в float, длина и обратная длина — в double;
умножение на обратную длину округляется обратно до float.
Смещение равно `dot(normal,sideVertex)-0.0006000000284984708`.
Точка блокирует ухо, если проходит все три проверки полупространств.
Unordered сравнения с NaN в этих проверках считаются проходящими,
как исходные `ja/jbe`.

В исходном внутреннем ABI normal передаётся как три значения xmm0..2,
vertices/indices/count/a/b/c — через обычные целочисленные регистры.
Одна деманглированная C++-сигнатура не описывает эту специализацию ABI.

## Записи треугольников и векторов

Функция не добавляет записи в конец меша. Она снимает последний индекс
из переданного пула освободившихся triangle slots. Для выбранных углов
a,b,c записывает вершины и cornerNormals в порядке **b,c,a**.
Surface/flags/state копируются из аргументов без изменения видимости.

Рёбра 0 и 1 соединяются с twins[a] и twins[b]; обновляются обратные ссылки.
Их edgeSource читаются из соседних треугольников. Для промежуточного уха
ребро 2 сначала не связано и имеет source=-1, а twins[a] заменяется
ссылкой на это ребро. Средний угол b удаляется стабильным сдвигом из
всех трёх массивов: vertices, normals, twins.
В последнем треугольнике ребро 2 соединяется с twins[c] с переносом его source.

После завершения размеры трёх входных векторов равны 0. Их старые хвостовые
байты не очищаются: сдвиги оставляют дубликаты прежних последних элементов.
Пул уменьшается на n-2, содержимое его массива не меняется.
TriangleMesh.triangleCount/vertexCount, ёмкости и world buffers не меняются.
Поля Triangle+72..107 и +113 сохраняют прежние байты целевого слота.
Для начального n<3 исходный helper возвращается без изменений векторов и пула.

## Граница безопасного интерфейса

Оригинал читает edgeSource соседа **даже при младших битах handle=3**.
Тогда физически читается Triangle+72, то есть первый brushIndex поля
brushEdges, за пределами массива edgeSource, но внутри записи Triangle.
При таком handle переносимая версия использует memcpy из байтов записи,
не обращаясь за границы C++-массива.

Старшие биты каждого входного handle обязаны указывать на существующий
triangle record, даже если младшие биты равны 3. В частности, `0xffffffff`
на входе отвергается. На оригинале такие выходящие за буфер обращения
намеренно не исполняются; экспериментальное падение не заявляется.
Нормальные внутренние диагонали, созданные helper, имеют действующие индексы.

Новый API принимает ConcavePolygonView и TriangleIndexPoolView с явными
count/capacity. Для n>=3 требуются n-2 разных действующих слотов пула,
отделённых от исходных граничных triangle records, допустимые индексы
вершин и поверхности. Все изменяемые буферы должны быть раздельными.
Гарантии проверены на этом домене; исходная функция не предоставляет
этих защит от недопустимого входа.

Изменения готовятся на копиях; ошибка сохраняет исходные массивы, меш,
размеры контура и пула. C ABI возвращает число переиспользованных треугольников,
0 для n<3, -1 для недопустимого входа, -2 для недостаточного пула,
-3 для прочих ошибок.

## Проверки

`tools/compare_concave_triangulation.py` исполняет неизменённые байты обоих
исходных helpers и сравнивает полные буферы, включая неизвестные поля и
свободную ёмкость. Проверяется SHA-256, используются раздельные страницы RX/RW.
Seed 1559, 5 000 наборов:

- 74 895 переиспользованных triangle slots;
- 162 возврата для контуров с 0..2 углами;
- 3 750 наборов в повёрнутых плоскостях с переносом координат;
- 968 повторов индексов вершин;
- 11 980 граничных handles с младшими битами 3 и доступной записью Triangle;
- ноль расхождений mesh, трёх полных входных массивов, пула и размеров векторов.

Набор включает выпуклые, звёздчатые, вырожденные, самопересекающиеся и
обратно ориентированные контуры, совпадающие позиции, очень малые и большие
масштабы, NaN и нулевые/обратные нормали. Исполнение на таких входах проверяет
точное поведение helper, а не геометрическую корректность полученного тела.

Семнадцатый CTest отдельно проверяет простой Г-образный контур с площадью 3:
точный порядок треугольников по оригиналу, положительный winding, площадь,
взаимные twins, нормали углов и граничные sources, остаток пула и хвосты массивов.
Также проверяются вырождения, bounded invalid handle и атомарность ошибок.
Все 17 CTest проходят в обычной сборке и ASan/UBSan
(`ASAN_OPTIONS=detect_leaks=0`).

```sh
cmake --build /tmp/realtime-csg-recovery/build
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
python3 tools/compare_concave_triangulation.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000
```
