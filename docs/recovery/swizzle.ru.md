# Swizzle: перестройка диагонали внутри Optimize

Реализация — `native/recovered/mesh_optimization.cpp`, интерфейс —
`native/include/realtimecsg/recovered_mesh_optimization.h`.
Перенесён `TriangleMesh::Swizzle(CSGBrushSurfaces const*, TriangleEdgeIndex)`
из macOS x86_64 RealtimeCSG 1.559, `0x331ae..0x339fe`,
SHA-256 `26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.
Функция не имеет прямых вызовов других функций и не выделяет память.
Она вызывается по `0x34533` из `RemoveVertexOnEdgeBetween2Surfaces`.
Эквивалентность Windows DLL не проверена.

## Вход и перестройка

Входное ребро принадлежит треугольнику A, его twin — треугольнику B.
Для каждого входного угла c определяются next=(c+1)%3, prev=(c+2)%3.
Назовём вершины P=A[next], Q=A[prev], R=B[next], S=B[prev].
Общая диагональ Q–S заменяется на P–R.
При успехе записи **всегда** переупорядочиваются так:

| Запись | Вершины | Twins |
| --- | --- | --- |
| A | R, S, P | B:0, старый B[prev], старый A[next] |
| B | P, Q, R | A:0, старый A[prev], старый B[next] |

Четыре внешних соседа получают обратные ссылки. Invalid handle определяется
по младшим двум битам 3 и переносится без нормализации битового представления.
Ссылки вершин обновляются в исходном порядке записей; итоговые P/Q/R/S handles
при четырёх различных индексах равны B:0, B:1, B:2, A:1.
Индексы треугольников, числа записей, ёмкости, позиции и world buffers не меняются.

## Геометрические решения

Первая кандидатная грань задаётся векторами u=Q-P, v=R-Q.
Вторая — u=S-R, v=P-S. Вычисления используют float и порядок сложений
исходных scalar SSE инструкций; слияние операций FMA отключено.

Восстановленные константы:

| Назначение | Float-биты | Значение |
| --- | --- | --- |
| Малое квадратное расстояние | `0x34c14607` | `3.6000002978653356e-7` |
| Малый квадрат cross | `0x2edbe6fe` | `9.999999439624929e-11` |
| Нижняя граница ratio | `0xbf7ffffe` | `-0.9999998807907104` |
| Верхняя граница ratio | `0x3f7ffffe` | `0.9999998807907104` |
| Множитель ориентации | `0x3727c5ac` | `9.999999747378752e-6` |

Ratio — `dot(u,v)/(|u|²*|v|²)`. В оригинале здесь **нет квадратного корня**;
замена на нормализованный cosine изменила бы решения.
Если любой из двух квадратов длин не больше малого расстояния, кандидат
допускается без остальных проверок. Иначе вычисляется cross и его квадрат.
При cross² ниже порога применяются дополнительные границы ratio:
ratio<=нижней границы отклоняется, ratio>=верхней допускается.
В остальных случаях требуется
`dot(cross,normal) >= cross²*orientationFactor`.
Unordered сравнение с NaN на этой последней проверке означает отказ.

Нормаль берётся из surface B, если первая грань не имеет коротких сторон и
либо cross² не меньше порога, либо сравнение `нижняяГраница >= ratio` ложно.
В остальных случаях выбирается surface A. Сначала проверяется вторая грань,
затем первая. Выбор A/B также определяет, чьи surface/flags/state переносятся
на другой треугольник. Отклонение не меняет буферы.

## Асимметрия исходных записей

Исходная функция меняет cornerNormals **только у A**, записывая
старые A[next], A[prev], B[next]. Нормали B остаются в старом порядке,
хотя его индексы вершин уже переставлены.
Аналогично A.edgeSource получает `[-1, старый A[prev], старый B[next]]`,
а B.edgeSource не переписывается. Остальные поля +72..107 и +113
не меняются. Это подтверждено сравнением всех байтов с машинным кодом.

Переносимый helper сохраняет это поведение. Он не обещает, что метаданные
уже готовы к конечному рендерингу: такие особенности нужно оценивать
при сборке полного конвейера, до возможной отдельной нормализации.

## Интерфейс и проверки

`swizzleTriangleEdge` возвращает bool. C ABI
`rcsg_recovered_swizzle_triangle_edge` возвращает 1 при перестройке,
0 при геометрическом отказе, -1 для некорректных входных данных,
-3 для прочих ошибок. До изменения памяти проверяются размеры буферов,
существование двух разных взаимных triangle twins, поверхности, читаемые
индексы вершин и доступность действующих внешних ссылок.
Буферы mesh должны быть отделены от surfaces. Самососедство A==B отвергается.
Исходный внутренний helper таких защит не предоставляет.

`tools/compare_swizzle.py` исполняет неизменённые байты исходной функции
на Linux x86_64 с проверкой хеша и защитой страниц RX/RW. Seed 1559:

- 5 000 наборов, все девять сочетаний углов A/B;
- 2 272 перестройки, 2 728 геометрических отказов;
- 872 входа с NaN/Infinity в позициях;
- 6 641 внешний invalid handle с разными битовыми представлениями;
- 648 случаев около float-порогов: длина, cross², нижний ratio и ориентация;
- ноль расхождений возвращённого решения, полных буферов треугольников,
  вершин и счётчиков.

Буферы заполнены случайными байтами: проверяются и неизвестные поля,
неиспользуемая ёмкость, произвольные нормали углов и теги. Пороговые входы
используют соседние float-представления. Это локальные индексированные
конфигурации, не проверка полного замкнутого CSG-тела.

Шестнадцатый CTest проверяет перестройку и обратные связи, выбор метаданных,
асимметричные записи нормалей/тегов, вырождение и неизменность буферов при
геометрическом отказе и ошибке входа. Все 16 CTest проходят обычную сборку
и ASan/UBSan (`ASAN_OPTIONS=detect_leaks=0`).

```sh
python3 tools/compare_swizzle.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
```

## Что остаётся внутри Optimize

Optimize (`0x34c44`) выделяет шесть временных векторов OptimizationContext,
затем вызывает RemoveVerticesInMiddleOfPlane (`0x34cf1`) и
RemoveVertexOnEdgeBetween2Surfaces (`0x34d06`).
Первая функция обходит вершины через RemoveVertexInMiddleOfPlane
(`0x316a2`), затем хвостовым переходом вызывает уже восстановленный
CleanUpRemovedVertices (`0x331a8 -> 0x32b82`).
RemoveVertexInMiddleOfPlane вызывает TriangulateConcavePolygon
(`0x31d67 -> 0x2f822`) и MergeBrushIndices (`0x3204f -> 0x3218e`).
Таким образом, вогнутая триангуляция нужна для следующей стадии оптимизации,
хотя в исследованном Create она не используется.

[Удаление одной вершины внутри плоскости также перенесено](plane-vertex-removal.ru.md).
[Внешний обход внутри плоскости также перенесён](plane-vertex-pass.ru.md).
[Второй проход и совместный Optimize теперь также перенесены](two-surface-pass.ru.md),

мешей](convex-mesh-preparation.ru.md); полный scene manager и интеграция Unity впереди.
