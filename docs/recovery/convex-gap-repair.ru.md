# Связывание подготовленных брашей и исправление стыков

`native/recovered/convex_gap_repair.cpp` добавляет `repairConvexGaps` к
[подготовке выпуклых мешей](convex-mesh-preparation.ru.md).
C++ API находится в `recovered_convex_csg.h`: массив `ConvexGapInput`,
целый бюджет разрезаний на каждый brush и `ConvexGapRepairResult` с
самостоятельными выходными мешами/группами и суммарным числом разрезаний.

Это **новая организация восстановленных функций в общем пространстве**.
Она не воспроизводит исходный scene manager и намеренно не вызывает macOS
FindConnections с обнаруженной адресацией по собственному brushIndex.
[Точная восстановленная FindConnections](connections.ru.md) не изменена:
её отдельный C ABI и сравнения с оригиналом сохраняют исходное поведение.
Эквивалентность исправленного поиска Windows DLL не заявляется.

## Поиск foreign connections

Для каждой группы на private copy:

1. Получаются уникальные foreign brush IDs из surfaceRefs, в порядке signed ID.
2. Рассматриваются группы **именно этого foreign brush**, с сохранением порядка
   их group indices. Ссылка на собственный brush или отсутствующий ID отклоняется.
3. У foreign-группы нужна ссылка на текущий brush и одну из его двух локальных
   surfaces. У текущей группы нужна ссылка на foreign brush и одну из surfaces
   foreign-группы. Одного совпадения бесконечных прямых недостаточно.
4. Требуется `abs(dot(directionA,directionB)) > 0.9999899864196777f` и квадрат
   расстояния до прямой `< 1.0000000116860974e-7f`. Оба направления линии
   допускаются. Расстояние проверяется в обе стороны, чтобы выбор был взаимным
   и не зависел от асимметрии округления проекции.
5. В `PreparedBrushEdgeGroup.connections` записываются реальные foreign brush ID
   и group index. Старые connections игнорируются и строятся заново.

Двунаправленная проверка поверхностей/прямой — правило нового адаптера,
а не утверждение о намерениях исходного C++. Segment overlap на этой стадии
не требуется: дальнейшие интервальные проверки пропускают несовпадающие участки.

Внутри вызова реальные IDs отображаются в плотные manager indices, чтобы
не выделять массив до максимального ID. У внешнего интерфейса ID могут быть
непоследовательными; наружу возвращаются реальные ID как в connections,
так и в TriangleRecord.brushEdges. Порядок выходных брашей совпадает со входом,
а обработка идёт по возрастанию реальных ID.

## Порядок исправления

1. Копируются полные подготовленные meshes/groups. Старые brushEdges сбрасываются.
   Для каждого brush создаются worldPositions и worldVertexLookup; в общем
   пространстве worldPositions равны локальным positions, transform identity.
2. Восстановленный [FixGaps](gap-dispatch.ru.md) вызывается для каждого brush.
   Он выполняет интервальные разрезания, обновляет source lists и выбирает
   соседей по видимости и нормалям. Foreign buffers независимы от local buffers.
3. Если были разрезания, выполняется ещё полный обход. Так точка, полученная
   промежуточным brush от одного соседа, достигает другого соседа в цепочке.
   Конец — полный обход без новых разрезаний; он также пересчитывает links
   после окончательного изменения геометрии соседей.
4. Затем восстановленный [ConnectGaps](mesh-cleanup.ru.md) ставит обратные ссылки.
5. Все vertex.edge handles обновляются обходом живых треугольников. Это необходимо,
   потому что исходный SplitTriangleEdgeIndex оставляет часть старых handles
   устаревшими. Triangle indices не перенумеровываются: cross-brush refs и
   group triangle lists остаются действительными.
6. В output groups копируются обновлённые triangle lists, brush IDs возвращаются
   из плотного внутреннего пространства в реальные, временные world buffers
   уничтожаются. Выход владеет всеми сохраняемыми данными.

Повторные обходы до отсутствия разрезаний и явное обновление vertex handles —
также новые правила организации. Они не объявляются исходным алгоритмом
UpdateTreeMeshes. Низкоуровневые восстановленные helpers не изменены.

## Ёмкости, бюджет и входы

По умолчанию бюджет 128 разрезаний **на brush суммарно за все обходы**.
При исходных T/V и бюджете B выделяются T+2B+2 треугольника и V+B+2 вершины.
Каждый source list получает исходный размер +2B: один cut добавляет максимум
два handle одной группе. Два запасных vertex slots учитывают проверку
нижнего SplitTriangleEdgeIndex. Размеры ограничены int/triangle-handle пределами.

Каждое разрезание увеличивает счётчик и расходует оставшийся бюджет.
Поэтому число обходов с разрезаниями ограничено; отдельного незавершающегося
поиска фиксированной точки нет. Недостаточный бюджет даёт length_error.

Входы — полные подготовленные замкнутые meshes, все упомянутые foreign brushes,
уникальные неотрицательные IDs, конечные позиции, единичные нормали плоскостей,
углов и направлений линий. Проверяются reciprocal twins и endpoint indices,
surface/state, соответствие каждого source tag ровно одной записи правильного
списка, отсутствие дубликатов и корректность foreign surface refs.
Старые connections/brushEdges могут быть устаревшими: они не используются.

Изменения всех brushes происходят на частных копиях. При ошибке бюджета,
индексов, planes или buffers исходные meshes, группы и поверхности не меняются,
даже если в рабочей сцене уже выполнены разрезания. Частичная сцена не возвращается.
Выход — per-brush топология с cross references, без общей сварки вершин.
Для видимого экспорта прежний `compactVisibleTriangles` очищает source tags
и cross refs, поскольку его triangle indices меняются.

## Проверки

Все прежние **740 булевых результатов** теперь выполняют:

```text
категоризация → подготовка групп/Create/Optimize/CleanUpBrushEdges
→ foreign resolver → FixGaps до обхода без разрезаний → ConnectGaps
→ обновление vertex handles → видимый экспорт
```

Стандартный прогон без трёх дополнительных OBJ-примеров:

| Показатель | Значение |
| --- | ---: |
| Дополнительные gap cuts | 19 |
| Направленные connections групп | 2 056 |
| Направленные cross-brush links углов | 1 946 |
| Треугольники после Optimize / после gap repair | 23 588 / 23 626 |
| Вершины после Optimize / после gap repair | 15 094 / 15 113 |

Сохранены проверки независимых объёма/площади, направления границы, точных
corner normals в этой выборке, flags/state и source surfaces. Дополнительно
проверяются действительные, не self ID/handles, взаимность connections и
triangle links, видимость обеих сторон, совпадение концов рёбер и полное
соответствие source tags обновлённым спискам. Для совпадения концов используется
расстояние <0.0045: исходный допуск интервальных параметров равен 1/256, а
линии также имеют небольшой поперечный допуск. Это не проверка глобальной сварки.

23-й CTest отдельно проверяет:

- пару тетраэдров с IDs 11/89, три разных foreign cuts, сохранение объёма 4/3;
- корректные real IDs, обновлённые source lists и старые vertex handles;
- неизменность входов после успеха и после исчерпания бюджета в ходе разрезаний;
- повторный запуск выровненной пары с бюджетом 0: ни новых cuts, ни изменений;
- цепочку 11↔37↔89, где крайние точки достигают друг друга через средний brush:
  шесть дополнительных cuts, в каждом теле семь вершин;
- отсутствие совпадения при односторонних refs/разнесённых параллельных линиях,
  допуск противоположного направления, строгую границу direction tolerance;
- отсутствующие/duplicate/self IDs, дубли source handles, испорченный twin,
  отрицательный бюджет и пустую сцену.

Цепочка — синтетическая проверка распространения подразделений на совпадающих
телах, а не категоризация такой сцены. Её тест проверяет per-brush топологию,
списки и объём; взаимность всех links отдельно проверяется на 740 CSG-результатах.

Все 23 CTest проходят обычную сборку и ASan/UBSan (`detect_leaks=0`).
Повторены регрессионные сравнения: 5 000 наборов FindConnections
(10 000 вызовов) и 2 000 полных вызовов FixGaps, без расхождений. Это отдельные oracle; новый foreign resolver не сравнивается с macOS self-lookup
как будто это одна и та же функция.

```sh
cmake --build /tmp/realtime-csg-recovery/build
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
/tmp/realtime-csg-recovery/build/recovered_convex_csg_tests /tmp/realtime-csg-recovery/gap-repaired-demo
```

Последняя команда создаёт OBJ union/subtract/intersect после gap repair.
Счётчики этой команды включают три дополнительных примера и отличаются
от таблицы стандартных 740 сценариев.

## Что остаётся

Существуют три разных вида связи: twins внутри исходного brush, foreign
connections между source groups и выбранные links между треугольниками.
Они ещё не являются объединённым сваренным manifold-мешем. Обработка
произвольного числа неоднозначных видимых кандидатов, касаний и вырождений
не доказана этой конечной выборкой; исходный ConnectGaps может перезаписывать
обратную ссылку при конкурирующих кандидатах.

Полный оригинальный Categorize/scene manager, произвольные относительные
transforms, broad phase и инкрементальные обновления ещё не реализованы.
[Новый scene bridge](scene-bridge.ru.md) уже выдаёт UV/нормали/тангенты,
материалы и единый Mesh; его C# P/Invoke проверен в Unity 2022.3.62f3 Linux.
Это отдельный ABI: подключение существующего редактора и проверка исходных
контрактов остаются впереди. Расширение геометрических проверок необходимо.
