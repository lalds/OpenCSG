# Первый восстановленный модуль: классификация относительно плоскости

На C++17 перенесены `CSGBrushPolygonMesh::Alignment` и
`VertexState::FindVertexSideOnPlane`. Код в `native/recovered/geometry.cpp`
собирается на Linux. Это исследовательский модуль, пока не замена Unity-плагина.

## Исходные доказательства

Источник: macOS x86_64 Mach-O, SHA-256
`26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.

| Объект | Адреса |
| --- | --- |
| `Alignment` | `0x2cc04` — `0x2cdfc` |
| `FindVertexSideOnPlane` | `0x2cdfe` — `0x2d15b` |
| Допуск +0.0006f | `0x3c554`, float bits `0x3a1d4952` |
| Допуск -0.0006f | `0x3c56c`, float bits `0xba1d4952` |
| Порог квадрата расстояния близких вершин | `0x3c57c`, float bits `0x34c14607` |
| Названия `PolygonSplitResult` | `0x40240`, 6 указателей |
| Названия `CategoryIndex` | `0x40270`, 4 указателя |

В этой сборке `__TEXT` имеет нулевые vmaddr/fileoff: адреса кода и float-констант
совпадают со смещениями в файле. Это свойство проверенного файла, не общее правило Mach-O.

`PolygonSplitResult`: CompletelyInside=0, CompletelyOutside=1, Split=2,
PlaneAligned=3, PlaneOppositeAligned=4, Collapsed=5.
`CategoryIndex`: Inside=0, Aligned=1, RevAligned=2, Outside=3.
Порядок этих двух enum отличается.

## Восстановленное поведение

Нативная формула: `((x*nx + y*ny) + z*nz) - plane.distance`.
Вычисления последовательные, в float, без FMA. Нормализации плоскости здесь нет.
Границы допуска включены: от `-0.0006000000284984708f` до
`+0.0006000000284984708f`. Порог квадрата расстояния вершин:
`3.6000002978653356e-7f`.

Вне допуска сторона определяется знаком. Внутри вызывается обработчик с двумя
изменяемыми значениями: `representativeEdge` (начальное -1), `cachedSide` (начальное -2).
Он просматривает обратные и прямые связи, выбирает среди близких вершин ту,
у которой меньше **знаковое** расстояние; останавливается на удалённой вершине
или выходе из допуска. Дополнительные обходы определяют сторону по вершинам вне
допуска. Представитель возвращает 0, другие вершины могут получить кэшированную
сторону. Сохранены наблюдаемые fallback и ограничители числа итераций.

`Alignment` возвращает Split при появлении обеих ненулевых сторон. Сравнение
нормалей применяется, когда все стороны нулевые. Collapsed эта функция не возвращает;
ноль рёбер даёт CompletelyInside.

Неожиданный, но воспроизведённый результат: синтетический квадрат
`(-1,-1,0), (1,-1,0), (1,1,0), (-1,1,0)` с циклическими прямыми/обратными
связями и плоскостью `(0,0,1,0)` возвращает CompletelyOutside.
Это наблюдается в оригинальном машинном коде и связано с общим кэшем между
вершинами. Пока не восстановлены инварианты реальных brush-данных, нельзя
объявлять это ошибкой плагина. Перенос сохраняет наблюдаемое поведение.

## Частичные структуры

Это внутренние записи, не публичные C#-структуры; для API нужен адаптер.

| Запись | Размер | Поля |
| --- | --- | --- |
| Полигон | 20 | +0 edgeCount, +4 firstEdge, +8 surfaceIndex |
| Half-edge | 16 | +0 nextEdge, +4 vertexIndex, +8 twinEdge, +12 polygonIndex |
| Дополнительная запись ребра | 8 | +0 previousEdge; +4 пока неизвестно |
| Позиция / плоскость | 12 / 16 | 3 float / 4 float |

Первые поля полигонального меша — указатели: +0 polygons, +8 edges,
+16 edgeLinks, +24 vertices. В BrushMemory счётчики читаются по +32 polygonCount,
+36 edgeCount, +40 vertexCount. Указатель плоскостей CSGBrushSurfaces — по +32.
Это не полные определения исходных классов.

Half-edge и обратные связи дополнительно подтверждены CreatePolygonWithVertices
(`0x61a0`) и InsertVertexBetweenEdges (`0x64b6`). Создание полигона записывает
байт PolygonFlags по +16 и `0xffff` по +18; Categorize использует +18 как
16-битное состояние. Окончательные типы остальных полей ещё не закреплены.

## Конвейер и следующий шаг

Успешная ветка PerformCSG (`0x1f7a4`): уничтожение старого TriangleMesh
(brush +0x60), получение brush mesh по индексу +0xd8, копирование BrushMemory,
Categorize, TriangleMesh::Create, освобождение копии, FlagInvisiblePolygons,
Optimize, CreateWorldSpaceVertices, CleanUpBrushEdges.
Шаг записи менеджера brush mesh — 0x68, BrushMemory внутри неё начинается по +0x30,
размер рабочей копии — 0x38. Семантика части аргументов и инварианты ещё исследуются.

CleanUpBrushEdges вызывается хвостовым `jmp` по `0x1f8ee`; прежний поиск только
`call` его пропускал. Теперь macho_audit.py сохраняет `tail_jump_candidates`.

В SplitByPlane (`0x2d15c`) подтверждены общий обработчик вершин, интерполяция
пересечения ребра, последовательная коррекция точки на режущую и исходную
плоскости, повторное использование близких вершин, InsertVertexBetweenEdges
и SplitAtEdges. Теперь они перенесены в отдельный
[модуль разрезания](splitting.ru.md).

## Сборка и сравнение

```sh
cmake -S native -B /tmp/realtime-csg-recovery/build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build /tmp/realtime-csg-recovery/build
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
python3 tools/compare_recovered_geometry.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 10000
```

CTest проверяет только восстановленный C++. Последняя команда вызывает две
изолированные исходные функции в процессе Linux x86_64. Копируются только их
байты и три константы с сохранением относительных адресов; после записи кодовые
страницы переключаются в RX. Их единственная внутренняя зависимость — вызов
Alignment → FindVertexSideOnPlane. Системные импорты, инициализация и остальная
библиотека не запускаются. Другой SHA-256 или архитектура отклоняются.

Проверено GCC 16.2.1, seed 1559: 10 000 классификаций и 130 662 вызова обработчика,
без расхождений результатов и обоих кэшей. Входы включают разные масштабы,
перестановки индексов, границы допуска, близкие/совпадающие вершины, пустые
и одновершинные записи. Это синтетические кольца с корректными индексами,
не доказательство всех инвариантов реального BrushMesh или полной эквивалентности.

Мутации BrushMemory и SplitByPlane уже проверяются с контролем замкнутости колец,
парности twin, числа полигонов и сохранения владельцев. Работа в Unity,
эквивалентность Windows DLL и полный CSG пока не проверялись.
