# TriangleMesh::Create

В `native/recovered/mesh_creation.cpp` перенесён вычислительный проход
`TriangleMesh::Create` из macOS x86_64 RealtimeCSG 1.559.
Интерфейс — `createTriangleMesh`, C ABI — `rcsg_recovered_create_triangle_mesh`.
Машинный блок: `0x30810..0x31150`; обычный возврат — `0x3103f`,
оставшийся хвост содержит освобождение временных векторов при исключениях.
SHA-256 источника:
`26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.
Windows DLL пока не использована для подтверждения этой функции.

## Что делает исходный проход

1. По `0x3082e..0x30929` удаляет грани с числом рёбер не больше двух.
   Для действующего firstEdge записывает edgeCount=0, firstEdge=-1,
   соединяет twin первого ребра с twin следующего и наоборот.
   После такого удаления перезапускает сканирование граней с нуля.
   Нулевые грани с отрицательным firstEdge пропускает.
2. Создаёт TriangleMesh и переносит **все** исходные позиции в TriangleVertex,
   включая неиспользуемые. Их начальный edge handle равен `0xffffffff`.
   Буферы world positions и lookup остаются пустыми.
3. Подготавливает временную таблицу half-edge → triangle-edge, изначально -1.
4. Для каждой оставшейся грани в исходном порядке собирает контур по nextEdge,
   xyz нормали её surface, существующие triangle twins из временной таблицы.
   По `0x30e3f` вызывает восстановленную TriangulateConvexPolygon.
5. По `0x30e6d..0x30ed0` переносит граничные edgeSource из EdgeLink+4,
   а для неотрицательных исходных twin записывает обратную привязку
   к полученным triangle-edge handles для последующих граней.

Оба статических вызова триангуляции в этом Create ведут в выпуклый helper.
Проверки выпуклости и вызова TriangulateConcavePolygon здесь нет.
Наличие отдельного символа вогнутой триангуляции не означает его применение
в этом проходе. Нулевая площадь треугольников сама по себе не удаляется.

Flags берутся из младшего байта Polygon+16, state — из Polygon+18.
Create сохраняет их без FlagInvisiblePolygons; видимость меняется позже.
Нормали копируются без нормализации. Поля Triangle+72..107 и +113 остаются
неинициализированными исходным проходом; переносимая функция сохраняет
предыдущее содержимое этих байтов в выходных буферах.

После первого прохода двухрёберных граней уже не остаётся. Второй исходный
цикл `0x308d3..0x30929`, снова проверяющий edgeCount==2, для проверенного
неизменяемого массива записей не добавляет действий.

## Переносимый интерфейс

Оригинал возвращает выделенный объект и может менять ёмкости через malloc,
free и libc++ vector. Новый API принимает пустой TriangleMeshView с заранее
выделенными буферами. Ёмкости принадлежат вызывающей стороне и не меняются;
политика выделения памяти оригинала не является частью совместимости.
Все выходные записи, перестройки twin и изменения Polygon выполняются на
временных копиях; ошибка не оставляет частичных изменений.

Проверяются размеры/ёмкости, действующие индексы поверхности и вершины,
доступные рёбра и замкнутость обходимого контура. Отрицательные edgeCount
отклоняются. Граничные twin<0 допускаются, как у оригинала, но при удалении
вырожденной грани оба перестраиваемых twin обязаны ссылаться на доступные
полурёбра. Буферы должны быть раздельными.

Коды C ABI: 0 — успех, -1 — недопустимый вход/топология,
-2 — недостаточная ёмкость, -3 — прочая ошибка.

## Сравнение с машинным кодом

`tools/compare_mesh_creation.py` исполняет весь исходный Create с неизменёнными
байтами функции и её helpers, проверкой SHA-256 и защитой страниц RX/RW.
Вызовы new/delete и malloc/free направлены в отслеживаемые host-обёртки.
Новые выделения заполнены `0xcc`; после каждого набора проверяются ошибки
освобождения и освобождаются оставшиеся буферы результата.
В оригинале реально исполняются и увеличение ёмкости, и перенос старых записей.

Seed 1559, 5 000 наборов:

- 98 096 итоговых треугольников;
- 3 149 подготовительных разрезаний плоскостью;
- 4 945 вставленных в подготовке двухрёберных/нулевых контуров;
- 715 синтетических однорёберных self-twin контуров;
- 2 161 случай роста исходной ёмкости треугольников сверх начальной оценки;
- 385 открытых наборов и 295 наборов с пустым списком граней;
- ноль расхождений.

Часть подготовленных контуров отбрасывается при переключении сценария на
открытый или пустой; счётчик вставок не равен числу реально удалённых граней.
Однорёберные self-twin входы проверяют управление потоком, а не корректность
геометрического тела. Поворот firstEdge меняется, нормали содержат произвольные
float-биты, включая NaN. Сравниваются все байты активных треугольников/вершин,
числа записей и полные исходные буферы, включая перестройки топологии.
В переносимом результате дополнительно проверяется неизменность свободной ёмкости.
Адреса выделений и значения capacity двух разных интерфейсов не сравниваются.

```sh
cmake --build /tmp/realtime-csg-recovery/build
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
python3 tools/compare_mesh_creation.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000
```

Пятнадцатый CTest проверяет удаление digon, взаимность triangle twins,
метаданные и неиспользуемые вершины, неизменность неизвестных полей и атомарность
ошибок. Все 15 CTest проходят в обычной сборке и ASan/UBSan
(`ASAN_OPTIONS=detect_leaks=0`).

## Интеграция и оставшиеся задачи

Исследовательский `triangulateConvexBrush` теперь вызывает восстановленный
Create на временной копии исходных Polygon/HalfEdge, затем применяет
восстановленные флаги видимости. Ранее добавленные 740 интеграционных проверок
объёма, площади и соседства проходят через этот путь.

Это восстанавливает конкретную функцию построения треугольников на проверенном
домене. Полный исходный Categorize, Optimize, решения по особенностям
FindConnections/MergeBrushIndices, выходные UV/материалы и Unity ABI остаются
отдельными задачами. Рабочая замена всего плагина этим не заявляется.
