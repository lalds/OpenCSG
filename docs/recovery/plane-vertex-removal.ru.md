# RemoveVertexInMiddleOfPlane

В `native/recovered/plane_vertex_removal.cpp` перенесён внутренний helper
`TriangleMesh::RemoveVertexInMiddleOfPlane`, macOS x86_64 RealtimeCSG 1.559,
`0x316a2..0x3207e`, SHA-256
`26789e84b0c11376582662bf1d53ed21a65c68d57449efb607070b266cb61a7d`.
Интерфейс добавлен в `recovered_mesh_optimization.h`.
Windows DLL пока не проверена.

Это удаление одной вершины с пометкой освободившихся записей, а не немедленное
уплотнение всего меша. Количества вершин и треугольников остаются прежними.
Внешний RemoveVerticesInMiddleOfPlane вызывает этот helper по `0x33187`,
не проверяет возвращённый bool и после обхода вызывает CleanUpRemovedVertices.

## Контекст из шести векторов

В оригинале OptimizationContext состоит из шести libc++ vector по 24 байта.
Переносимый PlaneOptimizationContextView содержит шесть буферов с count/capacity.

| Native offset | Переносимое имя | Назначение |
| --- | --- | --- |
| 0 | boundaryEdges | Сначала обходящие вершину handles, затем внешние граничные handles |
| 24 | removedTriangles | Пул освобождённых triangle slots, общий для последовательных вызовов |
| 48 | incidentTriangles | Уникальные треугольники текущего обхода |
| 72 | removedVertices | Накапливаемые удалённые вершины |
| 96 | polygonVertices | Вершины собираемого граничного контура |
| 120 | polygonNormals | Нормали соответствующих углов |

Размеры и содержимое scratch-векторов меняются и при некоторых отказах.
Содержимое неиспользуемой ёмкости не очищается.

## Обход и условия допуска

Исходный vertex.edge задаёт начальную сторону. Ссылка с младшими битами 3
приводит к возврату false без очистки контекста. Для остальных ссылок сначала
очищается boundaryEdges, затем проверяются индекс треугольника и его surface>=0.
После этих проверок очищается incidentTriangles.

Обход выполняет шаг `previous(twin(current))`, где previous меняет младшие
биты угла на `(corner+2)%3`. Первым в списки попадает следующий треугольник,
а начальный добавляется последним, при замыкании обхода.
Все посещённые треугольники должны иметь в точности одинаковые
surfaceIndex, flags и 16-битный categorizationState. Геометрические расстояния
до плоскости здесь не проверяются: helper полагается на эти метаданные.
При несовпадении возвращается false с уже собранной частью контекста.

После замыкания очищаются polygonVertices и polygonNormals. Для каждого
собранного handle берётся twin противоположной стороны. Он должен быть
действующей внешней стороной. Через его обратный twin выбираются вершина
и нормаль следующего угла исходного треугольника. Повтор уже собранного
индекса вершины приводит к отказу. BoundaryEdges постепенно заменяется
на внешние handles, так что отказ может оставлять смешанный список.

В ветви, где внешняя сторона принадлежит incidentTriangles, оригинал пробует
другую сторону, но последующая проверка всё ещё использует прежний индекс
треугольника. Эта ветвь заканчивается отказом; внешняя сторона в контекст
не записывается. Такой результат сохранён без придумывания обходного пути.

## Обычное удаление

После построения границы все incidentTriangles добавляются в removedTriangles
и получают surfaceIndex=-1. У удаляемой вершины edge становится `0xffffffff`,
её индекс добавляется в removedVertices.

Если контур содержит не две вершины, вызывается уже восстановленный
[TriangulateConcavePolygon](concave-triangulation.ru.md) с подготовленными
вершинами, нормалями, внешними twins и пулом removedTriangles.
Он переиспользует n-2 записей для нового участка, оставляя остальные в пуле
для последующего уплотнения. Helper возвращает true.
Для синтетического контура из одной вершины триангуляция ничего не строит,
но исходные записи уже помечены удалёнными, а результат всё равно true.

## Особый случай двух вершин

Триангуляция не вызывается. Оригинал выбирает пары сторон по принадлежности
треугольникам, при необходимости меняет внешние/внутренние стороны местами,
добавляет выбранные треугольники в пул без повторов и помечает их удалёнными.
Остающиеся стороны соединяются друг с другом, ссылки их конечных вершин
обновляются. Их edgeSource временно очищаются и передаются в
[MergeBrushIndices для пары](merge-brush-pair.ru.md), затем обе получают
возвращённый индекс группы.

**Эта ветвь возвращает false после изменения mesh, context и, при объединении,
BrushEdge groups.** Поэтому bool нельзя трактовать как «меш изменился» или
«операция не выполнилась». Сохранены также исходные remap-особенности парного
объединения. Списки граничных вершин и handles в этой ветви не очищаются.

## Переносимый контракт и атомарность ошибок

API `removeVertexInMiddleOfPlane` / `rcsg_recovered_remove_plane_vertex`
принимает явный planeCount, контекст и три переносимых массива групп.
C ABI возвращает исходные 0/1 либо -1 при некорректном входе,
-2 при недостатке ёмкости, -3 при прочей ошибке.
Возврат 0 является штатным исходным результатом и может сопровождаться
изменениями контекста или меша, описанными выше.

Нужен ограниченный замкнутый веер с индексированной границей и доступными
обратными ссылками. Проверяются диапазоны обращений и принадлежность
обходящей стороны удаляемой вершине; незамыкающийся цикл отвергается.
Недействительные retained handles в двухвершинной ветви не разыменовываются.
Все изменяемые буферы должны быть раздельными.

Вычисления и списки готовятся на копиях. В двухвершинной ветви потенциально
ошибающийся merge выполняется последним; он самостоятельно проверяет
ёмкости до записи групп. После его успеха остаются только записи полей и
копирование готовых буферов. Ошибки -1/-2/-3 сохраняют mesh, все шесть списков,
группы и groupCount. Это дополнительная гарантия переносимого интерфейса,
а не поведение исходных malloc/libc++ при ошибках.

## Сравнение с машинным кодом

`tools/compare_plane_vertex_removal.py` исполняет неизменённые байты всего
helper и зависимостей. SHA-256 проверяется; страницы кода RX, данных RW.
Stack guard направлен на действующее host-значение. Native-группы владеют
отслеживаемыми выделениями, поэтому оригинальные удаления/перестановки
и освобождения групп исполняются в сравнении.
Для шести векторов есть запас ёмкости; их native-пути роста не покрыты.

Два прогона по 5 000 входов, seed 1559:

| Метрика | Смешанный набор | Без намеренных отказов |
| --- | ---: | ---: |
| Native true | 363 | 3 763 |
| Native false с изменением меша | 112 | 1 237 |
| Случаи уменьшения числа групп | 46 | 504 |
| Двухвершинные вееры | 1 237 | 1 237 |
| Синтетические одновершинные вееры | 52 | 52 |
| Расхождения | 0 | 0 |

Смешанный набор включает некорректный начальный handle, отрицательную surface,
различающиеся surface/flags/state соседей, недействительную или внутреннюю
границу и повтор индекса граничной вершины. Проверяются частичные scratch-
изменения при каждом отказе. Контуры поворачиваются в пространстве; углы,
индексы записей и начальная сторона меняются. Нормали углов и неизвестные
поля имеют произвольные биты. Часть двухвершинных входов содержит две внешние
стороны одной записи и является синтетической проверкой вырожденной ветви.

Сравниваются все байты буферов треугольников, вершин, всех шести списков
вместе с неиспользуемой ёмкостью, их размеры, активные группы и три их списка.
Это пока отдельные вызовы на подготовленных веерах, не полный проход Optimize
по произвольной сцене.

Восемнадцатый CTest проверяет удаление центра плоского участка с сохранением
площади и отсутствие ссылок на него в живых треугольниках. Затем вызывается
восстановленный CleanUpRemovedVertices: число треугольников меняется с 8 на 6,
вершин — с 9 на 8, площадь сохраняется. Дополнительно проверяются двухвершинное
объединение групп с результатом false, scratch при отказе и атомарность
нехватки ёмкости как контекста, так и групп. Есть синтетический случай n=1.
Все 18 CTest проходят обычную сборку и ASan/UBSan (`ASAN_OPTIONS=detect_leaks=0`).

```sh
python3 tools/compare_plane_vertex_removal.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000
python3 tools/compare_plane_vertex_removal.py --library /tmp/realtime-csg-recovery/build/librealtimecsg_recovered_geometry.so --cases 5000 --removal-cases
ctest --test-dir /tmp/realtime-csg-recovery/build --output-on-failure
```
